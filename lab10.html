01

Matrix, list, edge list

18 min board

What to say

  • Before any algorithm: a graph is vertices plus edges, and there are three ways to hold it. Picking wrong is how a correct algorithm still fails.
  • Adjacency matrix — a[i][j], O(1) to ask "is there an edge", but O(n²) memory. At n = 10⁵ that is 10¹⁰ cells. Dead on arrival. Only usable up to about n = 2000.
  • Adjacency list — vector<vector<int>>, O(n + m) memory, iterate a vertex's neighbours directly. This is the default and should be their reflex.
  • Edge list — just the triples. Useless for traversal, essential for Kruskal in two weeks. Mention it and move on.
  • Then the reading habit: look at the constraints first. n ≤ 500 with a matrix in the statement means the matrix is intended; n ≤ 10⁵ means a list and nothing else.
  • Undirected means push both directions. Say it, write it, and say it again — a one-direction push in an undirected graph is the single most common silent bug in this lab.

For the board

vector<vector<int>> g(n + 1);

for (int i = 0; i < m; ++i) {
    int u, v; cin >> u >> v;
    g[u].push_back(v);
    g[v].push_back(u);   // undirected — both ways
}

02

BFS and why it finds shortest paths

20 min demo: grid

What to say

  • One rule: visit everything at distance 1, then everything at distance 2, and so on. The queue is what enforces that order.
  • Because of that layering, the first time BFS reaches a vertex it has reached it by a shortest path — in edges, on an unweighted graph. That is the theorem and it is worth stating precisely, including the two conditions.
  • The implementation detail that decides correctness: mark visited when you push, not when you pop. Marking on pop lets a vertex enter the queue several times and the complexity degrades.
  • Run the grid demo. Watch the wavefront expand ring by ring, and note the distance numbers appearing in non-decreasing order.
  • Complexity is O(n + m) — every vertex enters the queue once, every edge is examined once from each end.
  • Then the variants that cover most of the lab: multi-source (push every source with distance 0 — problem A), and BFS over states rather than places (problem C, where a vertex is a number and the edges are "×2" and "−1").

For the board

vector<int> dist(n + 1, -1);
queue<int> q;
q.push(s); dist[s] = 0;

while (!q.empty()) {
    int v = q.front(); q.pop();
    for (int to : g[v])
        if (dist[to] == -1) {
            dist[to] = dist[v] + 1;   // mark on push
            q.push(to);
        }
}
Two conditions on the theorem. Shortest in number of edges, and only on an unweighted graph. Put weights on the edges and BFS is simply wrong — that is lecture 13's problem, and Dijkstra is the fix.
The start-equals-finish case. The answer is 0, and a loop that only checks on expansion returns −1. Our own tests missed this until a test was added for it.

03

DFS — one word different

18 min board

What to say

  • Swap the queue for a stack — or just recurse — and the traversal goes deep first. Same O(n + m), completely different order.
  • State the asymmetry clearly: DFS does not give shortest paths. It finds a path, usually a long one. Every year somebody submits DFS for problem B.
  • What DFS gives instead is structure: connected components, cycle detection, topological order, bridges and articulation points.
  • Components — loop over all vertices, run DFS from each unvisited one, count the runs. Four lines, and it is problem F.
  • Cycle detection differs by graph type: undirected, any edge to a visited vertex that is not your parent; directed, you need three colours, because reaching a finished vertex is fine and only reaching a grey one is a cycle.
  • The practical warning: recursion depth equals path length. At n = 10⁵ a path graph overflows a default stack. On ejudge the import sets 256 MB so it survives — elsewhere convert to an explicit stack.

For the board

void dfs(int v) {
    used[v] = true;
    for (int to : g[v])
        if (!used[to]) dfs(to);
}

// count components
int comp = 0;
for (int v = 1; v <= n; ++v)
    if (!used[v]) { ++comp; dfs(v); }
Three colours for directed cycles. white = untouched, grey = on the current stack, black = finished. An edge to grey is a cycle; an edge to black is not. Using a single used array reports cycles that do not exist.

Topological sort

Order the vertices of a directed acyclic graph so every edge points forward. "Do the prerequisites first" — which is problem I word for word.

void dfs(int v) {
    used[v] = true;
    for (int to : g[v])
        if (!used[to]) dfs(to);
    order.push_back(v);      // AFTER the children
}
// then reverse(order)
Two things to check. The push must come after the recursion, and the result must be reversed. And if the graph has a cycle there is no valid order at all — the statement will have a word for that case, and you must detect it rather than print garbage.
04

Lab 10 — how it maps onto today

14 min ADS-Lab-10

What to say

  • Ten problems covering both lectures. The split is clean: A–D are BFS, F–J are DFS, and E is the outlier.
  • Start them on B and H. B is BFS on a matrix with n ≤ 100, H is DFS flood fill on a grid — between them they cover both traversals at minimum difficulty.
  • C is the one worth dwelling on: the vertices are numbers, not places. From A you can reach 2A and A−1. Once they see that, BFS-over-states unlocks a whole category.
  • F needs the undirected warning from beat 01 — a test exists specifically for the one-direction bug.
  • D and E are excluded from the defence. D is the heaviest (TL 5 s, repeated BFS with an amortisation argument); E is not a graph problem at all despite its name — it is three lookups in a matrix.

What comes next

3 min

Both remaining lectures are graphs with weights on the edges, which is exactly what breaks BFS. Lecture 12 asks for the cheapest way to connect everything — spanning trees, Kruskal and Prim. Lecture 13 asks for the cheapest way between two points — Dijkstra, Floyd and Bellman–Ford.

Note the calendar: the endterm falls between this lab and its defence. Lab 10 is defended in week 14, not week 13. Say the date explicitly.
