01

The prefix function

18 min demo: π table

What to say

  • Definition first, slowly: π[i] is the length of the longest proper prefix of s[0..i] that is also a suffix of s[0..i]. Proper means it is not the whole thing.
  • Do abacaba by hand on the board before any code: 0 0 1 0 1 2 3. Ask what π[6] = 3 is telling us — the first three characters equal the last three. That sentence is the entire lecture.
  • Naive computation is O(n³), and it is worth writing just to throw away. Then the improvement: when extending, if the next character does not match, fall back to π[j−1] instead of starting over.
  • The cost argument is the elegant part: j increases at most once per step and never goes below zero, so total fallbacks are at most n. Linear, amortised.
  • Step the demo on aabaaab and read the fallback chain out loud when it happens. Students accept the code long before they believe the complexity.

For the board

vector<int> pi(n, 0);
for (int i = 1; i < n; ++i) {
    int j = pi[i - 1];
    while (j > 0 && s[i] != s[j])
        j = pi[j - 1];          // fall back
    if (s[i] == s[j]) ++j;
    pi[i] = j;
}
a b a c a b a
0 0 1 0 1 2 3
Six lines, and two of them are traps. It is pi[j-1], not pi[j] — falling back to the wrong index loops forever. And the while must come before the if, or a failed match still increments.

02

Searching without ever going back

16 min board

What to say

  • The naive search, on a mismatch, moves the pattern one step and rereads the text. KMP never rereads — the text pointer only moves forward.
  • The trick is the concatenation: build pattern + separator + text and compute π over the whole thing. Wherever π[i] equals the pattern length, you have found an occurrence.
  • The separator must be a character that appears in neither string — # for lowercase input. Say why: without it a match can straddle the join and you count occurrences that do not exist.
  • Total cost O(n + m), deterministic, no probability, no collisions. That is the improvement over last week, and it is the whole reason this lecture exists.
  • Position arithmetic is where marks are lost: a match ending at index i in the combined string starts at i − 2·len in the original text. Derive it on the board rather than asserting it.

For the board

string cur = pat + '#' + txt;
vector<int> pi = prefixFunction(cur);

for (int i = 0; i < (int)cur.size(); ++i)
    if (pi[i] == (int)pat.size())
        cout << i - 2 * pat.size() << " ";
Memory, and it bites in this lab. The combined string is n + m + 1 characters and π is an int per character. With |s| = 5·10⁶ that is 20 MB for the array alone — fine at 256 MB, but do not also keep three copies of the string.
Overlapping matches count. Searching aa in aaaa gives three occurrences, not two. KMP reports all of them for free; a hand-rolled loop that resets on a match will not.

Three ways to find a substring

MethodTimeAlways rightExtra memory
NaiveO(n·m)yesO(1)

Worth saying out loud: in a contest most people reach for hashing because it is shorter to type. KMP is what you use when a wrong answer is not survivable — and when the problem wants π itself, which is most of this lab.

03

The array is worth more than the search

22 min demo: period

What to say

  • Here is the part that pays for the lecture. From π alone, with no extra work, you get several things that look like different problems.
  • Shortest period. n − π[n−1]. If it divides n, the string is that block repeated; otherwise it is a partial repetition. Problem G is this single expression.
  • All borders. π[n−1], then π of that minus one, and so on down to zero — the whole chain of prefixes that are also suffixes. This is the fallback chain made explicit.
  • Occurrence counting. Walk π backwards adding cnt[π[i]−1] += cnt[i] and you get how many times each prefix occurs in the string. Problem B needs exactly this.
  • Cyclic shift detection. t is a rotation of s if and only if t is a substring of s + s. One concatenation plus one KMP — problem C in two lines.
  • Let the demo show the period on abababab and on abababa: 2 in the first case, and in the second the period does not divide the length. That difference is the edge case every statement here hinges on.

The four one-liners

shortest period = n − π[n−1]
is fully periodic ⟺ n mod (n − π[n−1]) = 0
// how many times each prefix occurs
vector<int> cnt(n + 1, 0);
for (int i = 0; i < n; ++i) cnt[pi[i]]++;
for (int i = n - 1; i > 0; --i)
    cnt[pi[i - 1]] += cnt[i];
for (int i = 0; i <= n; ++i) cnt[i]++;   // itself
// is t a rotation of s?
bool rotation = s.size() == t.size() &&
                (s + s).find(t) != string::npos;

04

Lab 9 — how it maps onto today

12 min ADS-Lab-09

What to say

  • F is the plain search from beat 02 and should be done first — it is the template, and everything else reuses it.
  • G is beat 03's first formula, literally n − π[n−1]. If they have the array, the problem is one line; if they do not, it is impossible. Good demonstration of why the array matters more than the search.
  • C is the rotation trick, B is occurrence counting, D is longest overlap between a suffix and a prefix — all three are beat 03.
  • E and H are the heavy pair and neither is on the defence. E mixes the prefix function with arithmetic that overflows int at 5·10¹¹; H runs on a string of 5·10⁶ characters.
  • A is the awkward one to read: repeat A until B fits inside it. The answer is bounded by ⌈|B|/|A|⌉ + 1 — derive that bound with them, or they will loop forever.
