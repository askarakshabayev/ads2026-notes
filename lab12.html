01

Weights break BFS

16 min board

What to say

  • Open with a counter-example, not a definition. Two routes from A to D: one edge of weight 10, or three edges of weight 1 each. BFS picks the single edge because it counts edges. It is wrong.
  • So the fix is to explore by accumulated distance instead of by hop count. Replace the queue with a priority queue and the algorithm becomes Dijkstra. Literally one line different from lecture 10.
  • The invariant: when a vertex is popped, its distance is final. Everything still in the queue costs at least as much, so nothing can improve it later.
  • Relaxation is the only other idea: if d[v] + w < d[to], we found a better route, write it down and push.
  • Complexity O(m log n) with a binary heap. Mention that with an adjacency matrix and no heap it is O(n²), which is actually better on dense graphs — problem C is dense enough to care.
  • And the hard limit: Dijkstra requires non-negative weights. The invariant depends on it. Say it now, because beat 03 is what you do when it fails.

For the board

priority_queue<pair<long long,int>,
  vector<pair<long long,int>>,
  greater<>> pq;              // min-heap!

d[s] = 0; pq.push({0, s});
while (!pq.empty()) {
    auto [dv, v] = pq.top(); pq.pop();
    if (dv > d[v]) continue;      // stale entry
    for (auto [to, w] : g[v])
        if (d[v] + w < d[to]) {
            d[to] = d[v] + w;
            pq.push({d[to], to});
        }
}
Three traps in nine lines. Forget greater<> and you get a max-heap and nonsense. Forget the stale check and the complexity degrades. And initialise distances to something above the maximum possible path — LLONG_MAX then overflows on the addition, so use a large finite constant instead.

02

Watch it settle

16 min demo: dijkstra

What to say

  • Step the demo and read out what changes: the popped vertex turns final, its neighbours get tentative distances, and some of those get overwritten later.
  • Point at a vertex whose distance improves twice — that is relaxation doing its job, and it is why a single pass over the edges is not enough.
  • Then point at one that never improves after being popped. That is the invariant, visible.
  • Ask what happens if one edge is given weight −5. Let them predict, then say the answer: a vertex can be popped and then improved, and Dijkstra has no way to revisit it.
  • Mention path reconstruction, since one problem wants it: keep parent[to] = v on every successful relaxation, then walk back from the target and reverse.

03

All pairs, in five lines

16 min board

What to say

  • Different question: shortest distance between every pair. Running Dijkstra n times works, but there is something shorter and it handles negative edges.
  • The idea is one sentence: allow paths to pass through vertex 1, then also through 2, and so on. After allowing all n, every distance is final.
  • Write the triple loop and then say the thing that matters: k must be the outermost loop. Swap it with i or j and the algorithm is silently wrong — it compiles, runs, and gives plausible garbage.
  • O(n³) and O(n²) memory. At n = 500 that is 1.25·10⁸ operations — comfortable. At n = 1000 it is 10⁹ and borderline. That is why these statements cap n so low.
  • Initialisation: 0 on the diagonal, the edge weight where an edge exists, a large constant elsewhere. Use something like 10¹⁸/4 rather than LLONG_MAX, so that adding two of them does not overflow.
  • It handles negative edges fine; and if any d[i][i] ends up negative, the graph has a negative cycle — which is the next beat.

For the board

for (int k = 1; k <= n; ++k)       // OUTERMOST
  for (int i = 1; i <= n; ++i)
    for (int j = 1; j <= n; ++j)
      if (d[i][k] + d[k][j] < d[i][j])
        d[i][j] = d[i][k] + d[k][j];

Ask the room to say aloud what d[i][j] means after iteration k: the shortest path from i to j using only 1…k as intermediate vertices. That sentence is the proof.

Guard the addition. If both d[i][k] and d[k][j] are the "infinity" constant, their sum may wrap. Either check that both are below infinity before adding, or pick a constant small enough that doubling is safe.

Problem A is Floyd, incrementally

Vertices are added one at a time, and after each addition you report the sum of all shortest paths among the vertices added so far.

The trick is that this is Floyd read in the other direction: the k loop is "allow one more vertex". Add the vertices in reverse of the deletion order and each new vertex is exactly one k-iteration.

// after adding vertex k
for (int i = 1; i <= n; ++i)
  for (int j = 1; j <= n; ++j)
    d[i][j] = min(d[i][j], d[i][k] + d[k][j]);
// then sum over the already-added set
Same shape as problem E of lab 11. An operation that is hard forwards and easy backwards. Worth pointing out that this is a recurring trick, not a one-off.
04

Negative weights and negative cycles

16 min board

What to say

  • Bellman–Ford does not care about the order of exploration at all. It simply relaxes every edge, n − 1 times.
  • Why n − 1: a shortest path has at most n − 1 edges, and each pass extends the reach by at least one edge. Simple, slow, correct.
  • O(n·m), which at n = 100 is nothing. Only use it when Dijkstra cannot — that is, when weights can be negative.
  • The detection trick. Run one extra pass. If anything still improves, there is a negative cycle — a loop you can go round forever, getting cheaper. The shortest path is then undefined, not merely large.
  • To print the cycle rather than just report it: remember which vertex relaxed on the n-th pass, walk parent back n times to land inside the cycle, then walk until you return to that vertex. The "n times" step is the part everyone omits, and without it you print a tail that leads to the cycle instead of the cycle itself.
  • Close the course here: BFS, Dijkstra, Floyd and Bellman–Ford are one idea — relaxation — under four different orders of visiting.

For the board

for (int pass = 0; pass < n - 1; ++pass)
  for (auto& e : edges)
    if (d[e.u] + e.w < d[e.v]) {
      d[e.v] = d[e.u] + e.w;
      parent[e.v] = e.u;
    }

// one more pass — anything moving means a negative cycle
int x = -1;
for (auto& e : edges)
  if (d[e.u] + e.w < d[e.v]) { d[e.v] = d[e.u] + e.w; x = e.v; }
Walk back n times first. for (int i = 0; i < n; ++i) x = parent[x]; guarantees x is on the cycle. Skipping it prints the path leading into the cycle, which looks right on small tests and fails on the real ones.

Every one of them does the same update — if (d[u] + w < d[v]) d[v] = d[u] + w. They differ only in when they do it. That is a good last sentence for the course.

05

Lab 12 — how it maps onto today

12 min ADS-Lab-12

What to say

  • Five problems, one per algorithm, plus two that make you choose. Read the constraints with them and let the table from beat 01 do the work.
  • B is plain Dijkstra at N ≤ 10⁵ — the heap version, no alternative.
  • A is Floyd read backwards (beat 03), n ≤ 500. C is BFS on the complement graph at n ≤ 400 — the edges you can use are the ones that are not listed, which is a nice reminder that the graph in your head need not be the graph in the input.
  • D is the odd one and worth flagging as a good exam question: minimise the maximum edge on a path. That is not a shortest path, it is a bottleneck path — binary search the answer plus a reachability check, which brings lecture 3 back on the last day.
  • E is excluded from the defence — negative cycle detection plus printing the cycle, with more than one valid answer and its own checker.
  • Finally, the calendar: labs 11 and 12 are defended together, one problem from each lab in every variant.

06

End of the course

4 min

That is the syllabus. Thirteen lectures, twelve labs, from counting operations to shortest paths on weighted graphs.

Worth saying explicitly on the last day: the exam does not reward memorised code. It rewards the reflex from beat 01 — reading the constraints and naming the technique. n ≤ 20 means brute force; "minimum maximum" means binary search on the answer; "repeatedly the next smallest" means a heap; a weighted graph with non-negative edges means Dijkstra. Everything else is implementation.

Remind them the defence for labs 11 and 12 is the last graded item before the exam, and that the lab score still multiplies rather than adds — a lab left undefended is a lab worth zero, however many green ticks it has.
