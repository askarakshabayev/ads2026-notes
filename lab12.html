01

Shortest Path Problem Overview

6 min board

What to say

  • Two questions: from one source to every vertex, or between every pair.
  • Negative edges are allowed by some algorithms; a negative cycle makes the shortest path undefined — you could go round it forever.

Two problems

Given a weighted graph G = (V, E) with edge weights w(u, v):

  • Single-source shortest path (SSSP): the minimum-cost path from one source vertex s to all other vertices.
  • All-pairs shortest path (APSP): the minimum-cost path between every pair of vertices.
  • Negative-weight edges are allowed in some algorithms, but negative cycles make shortest paths undefined.
02

Dijkstra's Algorithm (Non-Negative Weights)

35 min code demo: Dijkstra

What to say

  • Goal: single-source shortest paths when all weights are non-negative.
  • Idea: repeatedly pick the unvisited vertex with the smallest current distance, then relax all its outgoing edges.
  • Relaxation is one line: if dist[v] + w < dist[to], a better route was found — update it and remember p[to] = v.
  • With a linear scan for the next vertex: O(V² + E). Fine for dense graphs and easy to read.
  • Walk through the small graph on the board, then step the demo on a random graph — the green vertices are final.
  • Then the other version: an undirected graph, and the path itself printed by walking p back from the target.

Idea and steps

Repeatedly pick the unvisited vertex with the smallest current distance, then relax all its outgoing edges — the straightforward O(V²) version.

  1. Initialise dist[v] = INF for all vertices, mark all unvisited; set dist[s] = 0.
  2. Repeat n times: choose the unvisited vertex v with the smallest dist[v] — if it is unreachable (INF), stop; mark v visited; for every edge (v, to, w), if dist[v] + w < dist[to], update dist[to] and record p[to] = v.
  3. After processing, dist holds the shortest distances from s.

Complexity and use cases

  • With a simple linear scan for the next vertex: O(V² + E) — often shown for clarity or for dense graphs.
  • Routing with non-negative costs: road networks, network latency.
  • A subroutine in A* search (with heuristics).

The program

Selects the next vertex with a linear scan instead of a priority queue. Vertices are 0 … n − 1, the graph is directed; input is n m s, then u v w per edge.

#include <bits/stdc++.h>
using namespace std;

const int INF = 1000000000;

int main() {
    int n, m, s; // vertices are 0..n-1
    cin >> n >> m >> s;
    vector<vector<pair<int, int>>> g(n);
    for (int i = 0; i < m; i++) {
        int u, v, w; cin >> u >> v >> w;
        g[u].push_back({v, w});
        // add g[v].push_back({u, w}); for an undirected graph
    }

    vector<int> d(n, INF), p(n, -1);
    vector<char> used(n, false);
    d[s] = 0;

    for (int i = 0; i < n; ++i) {
        int v = -1;
        for (int j = 0; j < n; ++j)
            if (!used[j] && (v == -1 || d[j] < d[v]))
                v = j;
        if (v == -1 || d[v] == INF)
            break;
        used[v] = true;

        for (auto [to, len] : g[v]) {
            if (d[v] + len < d[to]) {
                d[to] = d[v] + len;
                p[to] = v;
            }
        }
    }

    // d now holds shortest paths from s; p stores the tree for reconstruction
    for (int v = 0; v < n; v++)              // added: print the distances
        cout << (d[v] == INF ? -1 : d[v]) << " ";
    cout << "\n";
}

Bellman-Ford Algorithm (Handles Negative Weights)

25 min code

What to say

  • Goal: single-source shortest paths when weights can be negative, plus detection of a negative cycle reachable from the source.
  • Idea: relax every edge V − 1 times. A shortest path has at most V − 1 edges, and each pass extends the correct prefix by at least one edge.
  • One more pass: if anything still improves, there is a negative cycle.
  • O(V·E) — slower than Dijkstra; use it only when the weights force you to.

Idea and steps

Relax every edge V − 1 times; if an edge can still be relaxed once more, a negative cycle exists.

  1. Initialise dist[s] = 0, all others to INF.
  2. Repeat V − 1 times: for each edge (u, v, w), if dist[u] + w < dist[v], update dist[v].
  3. To detect negative cycles reachable from s, run one more pass; any improvement means a negative cycle.

Complexity and use cases

Cost
TimeO(V · E)
SpaceO(V)
  • Graphs with negative edges: currency arbitrage detection, balancing flows.
  • A preprocessing step before reweighting edges in Johnson's algorithm.

The program — edge list

#include <bits/stdc++.h>
using namespace std;

struct Edge { int u, v, w; };

int main() {
    const long long INF = 4e18;
    int n, m, s; // vertices 0..n-1
    cin >> n >> m >> s;
    vector<Edge> edges(m);
    for (auto &e : edges) cin >> e.u >> e.v >> e.w;

    vector<long long> dist(n, INF);
    dist[s] = 0;

    for (int i = 0; i < n - 1; i++) {
        bool changed = false;
        for (auto [u, v, w] : edges) {
            if (dist[u] != INF && dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                changed = true;
            }
        }
        if (!changed) break; // early exit if no updates
    }

    bool has_neg_cycle = false;
    for (auto [u, v, w] : edges) {
        if (dist[u] != INF && dist[u] + w < dist[v]) {
            has_neg_cycle = true;
            break;
        }
    }

    // dist holds shortest paths unless a reachable negative cycle exists
    if (has_neg_cycle) cout << "negative cycle\n";   // added: print the result
    else {
        for (int v = 0; v < n; v++)
            cout << (dist[v] == INF ? -1 : dist[v]) << " ";
        cout << "\n";
    }
}

Edges, in the order they are relaxed: 0→1 (4), 0→2 (5), 2→3 (-2), 3→1 (1).

Floyd–Warshall Algorithm (All-Pairs Shortest Paths)

22 min code

What to say

  • Goal: shortest paths between all pairs; negative edges are fine, negative cycles are not.
  • Idea: after processing vertices 0 … k, dist[i][j] is the shortest path from i to j that uses only those vertices in between.
  • Three nested loops, and k must be the outermost.
  • O(V³) time, O(V²) memory. A negative dist[i][i] at the end means a negative cycle.

Idea and steps

Dynamic programming over intermediate vertices: after processing vertices 0 … k, dist[i][j] stores the shortest path from i to j using only those as intermediates.

  1. Initialise dist[i][j] with the edge weights (INF if there is no edge) and dist[i][i] = 0.
  2. For each intermediate vertex k from 0 to V − 1, for each pair (i, j): dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j]).
  3. After the loops dist holds all-pairs distances. A negative cycle shows up as some dist[i][i] < 0.

Complexity and use cases

Cost
TimeO(V³)
SpaceO(V²)
  • Dense graphs where V³ is acceptable.
  • Transitive closure — replace the sums with boolean OR / AND.
  • Routing tables, or minimum distances inside DP over subsets (e.g. TSP).

The program — adjacency matrix

#include <bits/stdc++.h>
using namespace std;

int main() {
    const long long INF = 4e18;
    int n; // vertices 0..n-1
    cin >> n;
    vector<vector<long long>> dist(n, vector<long long>(n, INF));

    for (int i = 0; i < n; i++) dist[i][i] = 0;
    int m; cin >> m;
    for (int i = 0; i < m; i++) {
        int u, v, w; cin >> u >> v >> w;
        dist[u][v] = min(dist[u][v], 1LL * w); // handle multi-edges
    }

    for (int k = 0; k < n; k++)
        for (int i = 0; i < n; i++)
            for (int j = 0; j < n; j++)
                if (dist[i][k] < INF && dist[k][j] < INF &&   // fixed: never extend an unreachable path
                    dist[i][k] + dist[k][j] < dist[i][j])
                    dist[i][j] = dist[i][k] + dist[k][j];

    // dist[i][j] now holds APSP results
    for (int i = 0; i < n; i++) {             // added: print the matrix
        for (int j = 0; j < n; j++)
            if (dist[i][j] == INF) cout << "INF ";
            else cout << dist[i][j] << " ";
        cout << "\n";
    }
}

05

Choosing the Right Algorithm

5 min board

Which one when

  • Dijkstra: fast for non-negative weights and large sparse graphs.
  • Bellman-Ford: works with negative weights and detects negative cycles, but is slower.
  • Floyd–Warshall: all-pairs results for dense graphs; easy to adapt for path reconstruction or transitive closure.
