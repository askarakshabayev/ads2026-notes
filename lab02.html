01

Why a list at all

14 min demo: cost table

What to say

  • Last week the stack and the queue were STL boxes. Today we open them: underneath there is either an array or a chain of nodes, and the choice decides what is cheap.
  • The one sentence that carries the lecture: an array owns a contiguous block, a list owns only pointers. Everything else follows from that.
  • Insert in the middle of an array of a million elements moves half a million of them. In a list it is two assignments — but only once you already hold the node.
  • And that "only once you hold it" is the catch: getting to position i costs O(i). Make the room say out loud that a list has no random access.

Cost, side by side

Access i-thO(1)O(n)
Insert at frontO(n)O(1)

Cache behaviourcontiguousscattered
Say the unpopular half too: on modern hardware an array beats a list even at things the table calls O(n), because it walks memory in order. The list wins when you hold the node already and the data is huge.

02

Walk, insert, delete

18 min demo: playground

What to say

  • Traversal is the only way in: for (Node* p = head; p; p = p->next). Write it once and reuse it all lecture.
  • Insert after p is two lines, and the order matters: first hang the tail on the new node, only then rewire p->next. Do it in the wrong order on the board and lose the rest of the list on purpose.
  • Delete after p needs a saved pointer, otherwise the node leaks. Show Node* dead = p->next; p->next = dead->next; delete dead;.
  • Deleting the head is the special case every student forgets. Use the playground: pop_front and watch head itself move.
  • Mention the trick that removes the special case entirely — a dummy head node. It is the single best habit from this lecture.

03

The three classics

22 min demo: reverse, step by step

What to say

  • Reverse. Three pointers — prev, cur, nxt — and one rule: save the next node before you overwrite the link. Step the demo and read the three values out loud each time.
  • Middle. Two runners: slow moves one, fast moves two. When fast falls off the end, slow stands in the middle. One pass, no counting, no second traversal.
  • Ask which middle you get for an even length — the demo answers it. That ambiguity is exactly what problem E pins down in its statement.
  • Merge. Two sorted lists, one output: compare heads, take the smaller, advance. The tail that is left over is appended whole, not copied element by element — that is the point of using lists.
  • All three are O(n) time, O(1) extra memory. Say that out loud: no arrays, no vectors, no copying.

For the board

// reverse
Node* prev = nullptr;
Node* cur  = head;
while (cur) {
    Node* nxt = cur->next;   // save first!
    cur->next = prev;
    prev = cur;
    cur  = nxt;
}
head = prev;
// middle
Node *slow = head, *fast = head;
while (fast && fast->next) {
    slow = slow->next;
    fast = fast->next->next;
}
The line everyone drops: head = prev at the end of reverse. Without it head still points at what is now the last node, and the list looks empty from outside.

04

Two pointers per node

16 min board

What to say

  • Add prev to the node and two things become possible: walking backwards, and deleting a node you hold without knowing its predecessor. That second one is why std::list is doubly linked.
  • Deletion becomes symmetric — a->next = b->next; b->next->prev = a; — and the price is one extra pointer per element plus twice the rewiring on every insert.
  • Now close the loop with last week: std::deque is not this. It is a table of fixed blocks, which is why it has O(1) random access and a list does not. Students conflate the two every year.
  • Sketch where each one actually shows up: an LRU cache is a hash map plus a doubly linked list, a text editor undo stack is a list, a music player playlist is a circular one.

For the board

struct Node {
    int data;
    Node *prev, *next;
};

// erase a node we already hold
if (n->prev) n->prev->next = n->next;
else        head       = n->next;
if (n->next) n->next->prev = n->prev;
else        tail       = n->prev;
delete n;
Four branches, not two. Head and tail are both special. This is the exact shape of problem I, and it is where submissions die.

05

Lab 2 — how it maps onto today

14 min ADS-Lab-02

What to say

  • D, E and F are the three classics from beat 03, one each: reverse, middle, merge. They are solvable straight from the board.
  • I is the doubly linked list built by hand — the four-branch erase from beat 04. It is the heaviest problem of the lab, and the only one with a real maximum test.
  • Be honest with them about the rest. We measured it: every problem except I passes with a plain array or vector, because an array is never asymptotically worse here and is faster in practice.
  • So say where the requirement actually lives: at the defence. In D, E and F the notes now say it outright — you will be asked to show the pointers. A vector solution can be accepted by the judge and still score zero on the defence.
  • Repeat the limits: 1 second and 256 MB, except I at 2 s and J at 1.5 s.

What comes next

4 min

Lecture 3 is binary search — the first time this course trades a linear scan for a logarithmic one. Tell them the prerequisite out loud: it only works on something sorted and randomly accessible, which is exactly what a linked list is not. That contrast is the bridge from today.
