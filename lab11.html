01

Cheapest way to connect everything

14 min board

What to say

  • A spanning tree touches every vertex, is connected, and has no cycles. From those three words follows the count: exactly n − 1 edges, always. Derive it, do not assert it.
  • Minimum spanning tree = the spanning tree of least total weight. Note what it is not: it does not give shortest paths between pairs. That is next week and a different object.
  • Motivate it concretely — cable between buildings, roads between villages, water pipes. Every one of those is "connect all, pay least".
  • The property both algorithms rest on, the cut property: for any way of splitting the vertices into two groups, the cheapest edge crossing the split belongs to some MST. Say it once carefully; both algorithms are just different ways of exploiting it.
  • And the practical precondition: if the graph is disconnected there is no spanning tree at all. Every statement in this lab either guarantees connectivity or asks you to detect its absence.

For the board

a spanning tree of n vertices has exactly n − 1 edges

Why: a tree on n vertices has n − 1 edges (one per vertex beyond the first), and any n-th edge closes a cycle. So the algorithms can simply stop after n − 1 accepted edges.

The sum overflows int. With m up to 2·10⁵ and weights up to 10⁹, the total is up to 2·10¹⁴. Use long long for the answer — this is the standard first wrong answer in this lab.
MST is not unique when weights repeat, but its total is. That is why every problem here asks for the cost and not for the edge list — and why a checker comparing edge sets would be wrong.

Two directions, one answer

Kruskal — sort all edges, take the cheapest that does not close a cycle. Grows a forest that gradually merges into one tree. Thinks in edges.

Prim — start from one vertex, repeatedly attach the cheapest edge leaving the tree you already have. Grows one tree from the start. Thinks in vertices.

02

DSU — the structure that makes Kruskal work

22 min demo: union-find

What to say

  • Kruskal needs one question answered fast, millions of times: are these two vertices already connected? Running a DFS per edge would be O(m·n).
  • DSU answers it in almost constant time with two operations: find (which set is this in) and union (merge two sets).
  • The naive version is a forest of parent pointers and can degenerate into a chain — the same failure as an unbalanced BST. Two optimisations fix it, and both are one line.
  • Path compression: on the way back from find, point every node straight at the root. Union by size or rank: always hang the smaller tree under the larger.
  • Together they give O(α(n)) per operation — the inverse Ackermann function, below 5 for any input that fits in the universe. Call it "effectively constant" and do not prove it.
  • Use the demo: union a few pairs with compression off, watch the chain grow, then switch it on and watch the tree flatten.
  • Say where else DSU shows up, because it is the most reusable thing in this lecture: connectivity under added edges, cycle detection, counting components offline, and — read backwards — components under removed edges, which is exactly problem E.

For the board

int p[N], sz[N];

void make(int v) { p[v] = v; sz[v] = 1; }

int find(int v) {
    if (p[v] == v) return v;
    return p[v] = find(p[v]);   // path compression
}

bool unite(int a, int b) {
    a = find(a); b = find(b);
    if (a == b) return false;   // already together
    if (sz[a] < sz[b]) swap(a, b);   // by size
    p[b] = a; sz[a] += sz[b];
    return true;
}
Compare roots, not vertices. if (a == b) after both find calls. Comparing the raw arguments makes unite always succeed and the "tree" grows cycles.

03

Kruskal, then Prim

20 min demo: MST

What to say

  • Kruskal in three lines: sort the edges by weight; for each, if its ends are in different sets, take it and unite; stop at n − 1 edges.
  • Run the demo and narrate the rejections — an edge skipped is an edge that would have closed a cycle. That is the only thing DSU is being asked.
  • The correctness argument is the cut property from beat 01: the cheapest unused edge crossing any split is safe to take. Sketch it, do not belabour it.
  • Prim, for contrast: keep a priority queue of edges leaving the current tree, pop the cheapest, and if it reaches a new vertex, attach it. It is Dijkstra with one line changed — which is a useful thing to say now and collect next week.
  • If the loop ends with fewer than n − 1 edges, the graph was disconnected. That is not an error, it is an answer, and several statements ask for it.

For the board

sort(edges.begin(), edges.end());   // by weight

long long total = 0;
int taken = 0;
for (auto& e : edges) {
    if (unite(e.u, e.v)) {
        total += e.w;
        if (++taken == n - 1) break;
    }
}
if (taken < n - 1) /* disconnected */;

That is the whole algorithm. Everything else in this lecture exists to make unite fast.

04

Lab 11 — how it maps onto today

12 min ADS-Lab-11

What to say

  • Five problems. Four of them are Kruskal with a different story around it — say that early, it makes the lab look as small as it is.
  • D is the gentlest: n ≤ 50 given as a matrix, and the existing edges are the zero-weight ones. Build the edge list, run Kruskal, done.
  • B and C are Kruskal with the weights computed rather than given — from the island data in B, from the road type in C. The algorithm does not change; reading the weight rule does.
  • A is Kruskal at scale, n, m ≤ 2·10⁵, so the long long warning from beat 01 applies and the DSU must be the optimised one.
  • E is the odd one and it is excluded from the defence. Vertices are deleted one at a time and you count components — which is impossible forwards and easy backwards. Processing the queries in reverse turns deletion into union. It is a beautiful trick and too much for a 50-minute defence.

What comes next

3 min

Lecture 13 is the last one: shortest paths. Make the distinction explicit before they leave, because the two get confused every year — an MST connects everything at least total cost, a shortest-path tree gets you from one vertex to the others as cheaply as possible. They are usually different trees. Draw a triangle with weights 1, 1, 3 and show it in twenty seconds.

Note the calendar: labs 11 and 12 are defended together, in the final teaching week, with one problem from each. Say it now so nobody plans around two separate defences.
