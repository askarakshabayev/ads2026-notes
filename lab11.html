What Is a Minimum Spanning Tree?

12 min board

What to say

  • Given a connected, undirected, weighted graph G = (V, E), a spanning tree includes all vertices, has no cycles and has exactly |V| − 1 edges.
  • A minimum spanning tree is the spanning tree with the smallest total edge weight.
  • Where it is used: network design (roads, cables), clustering, image segmentation, approximations for hard optimisation problems.
  • Put the example graph on the board — it is used by both algorithms for the rest of the lecture.

Spanning tree and MST

A spanning tree of G = (V, E) is a subgraph that:

  • includes all vertices in V
  • is a tree (no cycles)
  • has exactly |V| − 1 edges

A minimum spanning tree (MST) is the spanning tree with the smallest possible total edge weight. MSTs are used in network design (roads, cables), clustering, image segmentation, and approximations for hard optimisation problems.

Key Properties of MSTs

8 min board

What to say

  • Exactly |V| − 1 edges and no cycles — so an algorithm can stop after |V| − 1 accepted edges.
  • The cut property is what both algorithms rely on: the lightest edge crossing any cut belongs to some MST.
  • The cycle property is the mirror image: the heaviest edge of a cycle is never needed.

Four properties

  • An MST has exactly |V| − 1 edges and no cycles.
  • Adding any edge to the MST creates a cycle; removing any MST edge disconnects the graph.
  • Cut property: for any cut (partition of the vertices), the lightest edge crossing the cut belongs to at least one MST.
  • Cycle property: in any cycle, the heaviest edge cannot be in an MST.

Kruskal's Algorithm

35 min code demo: union-find demo: Kruskal

What to say

  • Idea: sort the edges by weight and add them one by one, skipping every edge that would create a cycle.
  • To detect a cycle quickly we need one question answered fast: are u and v already connected? That is the Disjoint Set Union — find and unite.
  • Show the DSU demo: union a few pairs with the naive version, watch the chain grow, then switch to the optimised one — path compression and union by rank.
  • Then the code: the DSU, the edge with operator<, and main — sort, unite, stop at n − 1 edges.
  • Walk through the example on the board, then let the Kruskal demo do a random graph.
  • Total O(E log E) — the sort dominates; each DSU operation is almost O(1).

Idea and steps

Sort edges by weight and add them one by one, skipping edges that would create a cycle. A Disjoint Set Union (DSU), also called Union-Find, quickly detects cycles.

  1. Sort all edges in non-decreasing order of weight.
  2. Initialise the DSU so each vertex is its own set.
  3. For each edge (u, v, w) in order: if find(u) != find(v), add the edge to the MST and union the sets.
  4. Stop when |V| − 1 edges are chosen.

Complexity

PartCost
Sorting edgesO(E log E)
DSU operationsalmost O(1) each (inverse Ackermann)
TotalO(E log E)

1 · The DSU

struct DSU {
    vector<int> parent, rank;
    DSU(int n) : parent(n), rank(n, 0) {
        iota(parent.begin(), parent.end(), 0);
    }
    int find(int v) {
        if (parent[v] == v) return v;
        return parent[v] = find(parent[v]); // path compression
    }
    bool unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return false;          // already in same set
        if (rank[a] < rank[b]) swap(a, b); // union by rank
        parent[b] = a;
        if (rank[a] == rank[b]) rank[a]++;
        return true;
    }
};

find returns the root of the set and, on the way back, points every node straight at it (path compression). unite hangs the lower tree under the higher one (union by rank) and returns false when both ends are already in one set — that edge would close a cycle.

2 · The edge

struct Edge {
    int u, v, w;
    bool operator<(const Edge& other) const { return w < other.w; }
};

operator< compares by weight, so sort puts the lightest edges first.

3 · main

int main() {
    int n, m;
    cin >> n >> m;
    vector<Edge> edges;
    edges.reserve(m);
    for (int i = 0; i < m; i++) {
        int x, y, w;
        cin >> x >> y >> w;
        edges.push_back({x - 1, y - 1, w});
    }

    sort(edges.begin(), edges.end());
    DSU dsu(n);

    int mst_cost = 0;
    vector<Edge> mst;

    for (auto &e : edges) {
        if (dsu.unite(e.u, e.v)) {
            mst.push_back(e);
            mst_cost += e.w;
        }
        if ((int)mst.size() == n - 1) break;
    }

    cout << "MST cost: " << mst_cost << "\nEdges:\n";
    for (auto &e : mst) {
        cout << e.u + 1 << " - " << e.v + 1 << " (" << e.w << ")\n";
    }
    return 0;
}

Prim's Algorithm

30 min code

What to say

  • Idea: grow the MST from a start vertex, each time taking the lightest edge that connects the tree to a new vertex.
  • The dense version: key[v] is the lightest edge from the tree to v. Pick the unused vertex with the smallest key, mark it, update the keys of its neighbours.
  • This is O(V²); with a min-heap it becomes O(E log V).
  • Walk through the example from vertex 1 and show that the cost is the same 13 as Kruskal.
  • Then the two other versions: one that remembers the parent and prints the edges, and one that uses −1 for "not reached yet" — and the trap that comes with it.

Idea and steps

Grow the MST from an arbitrary start vertex by repeatedly picking the minimum-weight edge that connects the current tree to a new vertex. Below is the dense O(V²) version — scan all vertices to find the next minimum key. A min-heap version improves it to O(E log V).

  1. Set key[start] = 0, all others to infinity.
  2. Repeat n times: pick the unused vertex v with the smallest key[v]; mark v used; for each neighbour (to, w), if w < key[to], update key[to] and record the parent.
  3. The keys of the chosen edges and the parents describe the MST.

Complexity

VersionCost
Dense scan (below)O(V²)
With a binary heapO(E log V)

The program

#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, m;
    cin >> n >> m;
    vector<vector<pair<int, int>>> g(n);
    for (int i = 0; i < m; i++) {
        int x, y, w;
        cin >> x >> y >> w;
        --x; --y;
        g[x].push_back({y, w});
        g[y].push_back({x, w});
    }

    const int INF = 1e9;
    vector<int> key(n, INF), parent(n, -1), used(n, 0);

    key[0] = 0; // start from vertex 0
    for (int i = 0; i < n; i++) {
        int v = -1;
        for (int j = 0; j < n; j++) {
            if (!used[j] && (v == -1 || key[j] < key[v])) v = j;
        }
        used[v] = 1;
        for (auto [to, w] : g[v]) {
            if (!used[to] && w < key[to]) {
                key[to] = w;
                parent[to] = v;
            }
        }
    }

    int total = 0;
    for (int w : key) total += w;

    cout << "MST cost: " << total << "\nEdges:\n";
    for (int v = 1; v < n; v++) {
        cout << parent[v] + 1 << " - " << v + 1 << " (" << key[v] << ")\n";
    }
    return 0;
}

Another version · −1 instead of infinity

Here "not reached yet" is −1 instead of a large number. Then choosing the next vertex needs an extra condition: an unreached vertex must never be picked while a reached one is available.

        int v = -1;
        for (int j = 0; j < n; j++) {
            // fixed: skip unreached vertices (d == -1), otherwise one could be picked
            if (u[j] == 0 && d[j] != -1 && (v == -1 || d[v] > d[j]))
                v = j;
        }

Without d[j] != -1 the first unused vertex is taken as the starting candidate even when it is unreached, and d[v] > d[j] with d[v] = -1 is never true, so it is never replaced.

Takeaways

3 min

Four things to remember

  • MSTs connect all vertices with minimum total weight and no cycles.
  • Kruskal: sort the edges, add the lightest non-cycle edges using DSU.
  • Prim: grow from a start vertex, always choose the lightest outgoing edge.
  • Both algorithms give the same MST cost on connected undirected weighted graphs.
