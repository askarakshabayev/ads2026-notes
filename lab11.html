What Is a Minimum Spanning Tree?

12 min board

Spanning tree and MST

A spanning tree of G = (V, E) is a subgraph that:

  • includes all vertices in V
  • is a tree (no cycles)
  • has exactly |V| − 1 edges

A minimum spanning tree (MST) is the spanning tree with the smallest possible total edge weight. MSTs are used in network design (roads, cables), clustering, image segmentation, and approximations for hard optimisation problems.

02

Key Properties of MSTs

15 min board demo: cut and cycle

Four properties

  • An MST has exactly |V| − 1 edges and no cycles.
  • Adding any edge to the MST creates a cycle; removing any MST edge disconnects the graph.
  • Cut property: for any cut (partition of the vertices), the lightest edge crossing the cut belongs to at least one MST.
  • Cycle property: in any cycle, the heaviest edge cannot be in an MST.

What a cut is

A cut splits the vertices into two non-empty groups S and V − S. An edge crosses the cut if one end is in S and the other is not. Every spanning tree must connect the two groups, so it contains at least one crossing edge — the cut property says which one is always safe to take: the lightest.

On the example: the cut {1} | {2, 3, 4, 5, 6} is crossed by (1,2,1), (1,3,5), (1,4,8), (1,5,3). The lightest, (1,2,1), is in the MST. The cycle 1 – 3 – 4 – 1 has weights 5, 4, 8; the heaviest, (1,4,8), is not in the MST.

Why the cut property holds

Let e be the lightest edge crossing a cut, and suppose some MST T does not contain e.

  1. Add e to T. A tree plus one edge has exactly one cycle.
  2. That cycle crosses the cut through e, so it must cross back through another edge f of the cut.
  3. e is the lightest crossing edge, so w(f) ≥ w(e).
  4. T + e − f is again a spanning tree, and its weight is not larger than T. So it is also an MST — and it contains e.

Why the cycle property holds

Let e = (u, v) be the strictly heaviest edge of a cycle C, and suppose an MST T contains e.

  1. Remove e from T. The tree falls apart into two parts: one with u, one with v. That is a cut.
  2. The rest of C still leads from u to v, so some other edge f of C crosses this cut.
  3. f is on the same cycle, so w(f) < w(e).
  4. T − e + f is a spanning tree lighter than T — a contradiction. (With equal weights the statement becomes: some MST avoids e.)

In short: if u and v can be reached around the cycle with cheaper edges, the most expensive edge of that cycle is never needed.

03

Prim's Algorithm

30 min code

Idea and steps

Grow the MST from an arbitrary start vertex by repeatedly picking the minimum-weight edge that connects the current tree to a new vertex. Below is the dense O(V²) version — scan all vertices to find the next minimum key. A min-heap version improves it to O(E log V).

  1. Set key[start] = 0, all others to infinity.
  2. Repeat n times: pick the unused vertex v with the smallest key[v]; mark v used; for each neighbour (to, w), if w < key[to], update key[to] and record the parent.
  3. The keys of the chosen edges and the parents describe the MST.

Why this is correct: at every step the edge taken is the lightest edge of the cut “tree | everything else” — exactly the cut property.

Complexity

VersionCost
Dense scan (below)O(V²)
With a binary heapO(E log V)

The order of attaching is 1, 2, 5, 6, 3, 4 — five edges, cost 13.

The program

#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, m;
    cin >> n >> m;
    vector<vector<pair<int, int>>> g(n);
    for (int i = 0; i < m; i++) {
        int x, y, w;
        cin >> x >> y >> w;
        --x; --y;
        g[x].push_back({y, w});
        g[y].push_back({x, w});
    }

    const int INF = 1e9;
    vector<int> key(n, INF), parent(n, -1), used(n, 0);

    key[0] = 0; // start from vertex 0
    for (int i = 0; i < n; i++) {
        int v = -1;
        for (int j = 0; j < n; j++) {
            if (!used[j] && (v == -1 || key[j] < key[v])) v = j;
        }
        used[v] = 1;
        for (auto [to, w] : g[v]) {
            if (!used[to] && w < key[to]) {
                key[to] = w;
                parent[to] = v;
            }
        }
    }

    int total = 0;
    for (int w : key) total += w;

    cout << "MST cost: " << total << "\nEdges:\n";
    for (int v = 1; v < n; v++) {
        cout << parent[v] + 1 << " - " << v + 1 << " (" << key[v] << ")\n";
    }
    return 0;
}

Another version · −1 instead of infinity

Here "not reached yet" is −1 instead of a large number. Then choosing the next vertex needs an extra condition: an unreached vertex must never be picked while a reached one is available.

        int v = -1;
        for (int j = 0; j < n; j++) {
            // fixed: skip unreached vertices (d == -1), otherwise one could be picked
            if (u[j] == 0 && d[j] != -1 && (v == -1 || d[v] > d[j]))
                v = j;
        }

Without d[j] != -1 the first unused vertex is taken as the starting candidate even when it is unreached, and d[v] > d[j] with d[v] = -1 is never true, so it is never replaced.

04

Disjoint Set Union (DSU)

25 min board demo: DSU code

The problem

We keep several disjoint sets of elements and need three operations:

  • make_set(v) — create a new set {v};
  • union_sets(a, b) — merge the set containing a with the set containing b;
  • find_set(v) — return the representative (the “name”) of the set containing v.

Two elements are in the same set exactly when find_set(a) == find_set(b). Kruskal asks this question for every edge: are u and v already connected? If yes, the edge would close a cycle.

How the sets are stored

Each set is a tree. Every vertex stores only its parent, p[v]; the root has p[root] = root and is the representative of the set.

sets {1, 2, 3, 4} and {5, 6}

     1          5         v    : 1 2 3 4 5 6
    / \         |         p[v] : 1 1 1 3 5 5
   2   3        6
       |
       4

find_set(4) climbs 4 → 3 → 1 and stops at the root 1. union_sets(4, 6) finds the two roots, 1 and 5, and hangs one under the other: p[5] = 1. That is the whole data structure — one array.

1 · The naive version

int p[N];

void make_set(int v) {
    p[v] = v;                    // a new set {v}; v is its own root
}

int find_set(int v) {
    if (v == p[v]) return v;     // v is the root
    return find_set(p[v]);       // otherwise climb to the parent
}

void union_sets(int a, int b) {
    a = find_set(a);
    b = find_set(b);
    if (a != b) p[b] = a;        // hang the root of b under the root of a
}

It is correct, but the trees can turn into long chains: scenario 2 in naive mode builds 1 → 2 → … → 8, and every find_set(8) then walks 7 steps. In the worst case one operation is O(n).

2 · Path compression

int find_set(int v) {
    if (v == p[v]) return v;
    return p[v] = find_set(p[v]);   // remember the root on the way back
}

After the call every vertex on the path points directly to the root. The path was walked once anyway; now the next find_set from any of those vertices takes one step.

3 · Union by rank

int p[N], r[N];                  // r[v] — rank: an upper bound on the height of v's tree

void make_set(int v) {
    p[v] = v;
    r[v] = 0;
}

void union_sets(int a, int b) {
    a = find_set(a);
    b = find_set(b);
    if (a == b) return;              // already in one set
    if (r[a] < r[b]) swap(a, b);     // a is now the taller tree
    p[b] = a;                        // the lower tree goes under the taller one
    if (r[a] == r[b]) r[a]++;        // two equal heights: the result is one taller
}

Always hang the lower tree under the taller one. The height grows only when two trees of equal rank are merged, so a tree of rank k has at least 2k vertices and the height never exceeds log₂ n.

Complexity

Versionfind_set / union_sets
naiveO(n) in the worst case
path compression onlyO(log n) amortised
union by rank onlyO(log n)
both togetherO(α(n)) amortised — α is the inverse Ackermann function, at most 4 for any real n

The lecture code (the DSU struct in Kruskal below) uses both: parent[v] = find(parent[v]) is the compression, the rank array is union by rank.

05

Kruskal's Algorithm

35 min code demo: Kruskal

Idea and steps

Sort edges by weight and add them one by one, skipping edges that would create a cycle. A Disjoint Set Union (DSU), also called Union-Find, quickly detects cycles.

  1. Sort all edges in non-decreasing order of weight.
  2. Initialise the DSU so each vertex is its own set.
  3. For each edge (u, v, w) in order: if find(u) != find(v), add the edge to the MST and union the sets.
  4. Stop when |V| − 1 edges are chosen.

Why this is correct: an edge that joins two different sets is the lightest edge leaving its set (cut property); an edge inside one set closes a cycle in which it is the heaviest, since all the others were taken earlier (cycle property).

Complexity

PartCost
Sorting edgesO(E log E)
DSU operationsalmost O(1) each (inverse Ackermann)
TotalO(E log E)

1 · The DSU

struct DSU {
    vector<int> parent, rank;
    DSU(int n) : parent(n), rank(n, 0) {
        iota(parent.begin(), parent.end(), 0);
    }
    int find(int v) {
        if (parent[v] == v) return v;
        return parent[v] = find(parent[v]); // path compression
    }
    bool unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return false;          // already in same set
        if (rank[a] < rank[b]) swap(a, b); // union by rank
        parent[b] = a;
        if (rank[a] == rank[b]) rank[a]++;
        return true;
    }
};

find returns the root of the set and, on the way back, points every node straight at it (path compression). unite hangs the lower tree under the higher one (union by rank) and returns false when both ends are already in one set — that edge would close a cycle.

2 · The edge

struct Edge {
    int u, v, w;
    bool operator<(const Edge& other) const { return w < other.w; }
};

operator< compares by weight, so sort puts the lightest edges first.

3 · main

int main() {
    int n, m;
    cin >> n >> m;
    vector<Edge> edges;
    edges.reserve(m);
    for (int i = 0; i < m; i++) {
        int x, y, w;
        cin >> x >> y >> w;
        edges.push_back({x - 1, y - 1, w});
    }

    sort(edges.begin(), edges.end());
    DSU dsu(n);

    int mst_cost = 0;
    vector<Edge> mst;

    for (auto &e : edges) {
        if (dsu.unite(e.u, e.v)) {
            mst.push_back(e);
            mst_cost += e.w;
        }
        if ((int)mst.size() == n - 1) break;
    }

    cout << "MST cost: " << mst_cost << "\nEdges:\n";
    for (auto &e : mst) {
        cout << e.u + 1 << " - " << e.v + 1 << " (" << e.w << ")\n";
    }
    return 0;
}

Another version · edges as pairs

The edge is stored as pair<w, pair<x, y>>, so plain sort orders by weight with no comparator. The DSU is two arrays and two functions:

int find(int v) {
    if (p[v] == v)
        return v;
    p[v] = find(p[v]);
    return p[v];
}

void union_set(int v, int u) {
    v = find(v);
    u = find(u);
    if (r[v] < r[u])
        p[v] = u;
    else if (r[u] < r[v])
        p[u] = v;
    else {
        p[u] = v;
        r[v]++;
    }
}

Takeaways

3 min

Four things to remember

  • MSTs connect all vertices with minimum total weight and no cycles.
  • Prim: grow from a start vertex, always choose the lightest outgoing edge.
  • Kruskal: sort the edges, add the lightest non-cycle edges using DSU.
  • Both algorithms give the same MST cost on connected undirected weighted graphs.
