01

Guess the number

16 min demo: search stepper

What to say

  • Open with the game: I picked a number from 1 to 1000, you have ten guesses. Someone will say 500. Ask why — that answer is the whole lecture.
  • Each comparison throws away half the candidates. n → n/2 → n/4 → … → 1 takes log₂n steps. For a million that is 20, for a billion 30.
  • Two preconditions, and they are non-negotiable: the data is sorted, and you can jump to the middle in O(1). Say out loud that this is exactly what a linked list cannot do — that is the bridge from last week.
  • Run the demo on n = 100 and then on n = 10⁹ and let them read the step count. Linear search on 10⁹ is a billion comparisons; this is thirty.

For the board

int l = 0, r = n - 1;
while (l <= r) {
    int m = l + (r - l) / 2;   // not (l+r)/2
    if (a[m] == x) return m;
    if (a[m] < x) l = m + 1;
    else          r = m - 1;
}
return -1;
Why l + (r-l)/2: with l and r near 2·10⁹ the sum l+r overflows int and the index goes negative. This is the famous bug that sat in the JDK for nine years — worth the thirty seconds it takes to tell.
The other classic: writing l = m instead of l = m + 1. The range stops shrinking and the loop hangs. If a submission times out on a tiny test, this is why.

02

The two versions you actually use

18 min demo: duplicates

What to say

  • The textbook version answers is it there. Real problems ask where is the first one ≥ x or how many are < x. That is lower_bound.
  • Switch the loop to while (l < r) with r = n — the answer is a position, possibly n, not an index that must exist. This off-by-one is where most of the lab is lost.
  • With duplicates: lower_bound gives the first occurrence, upper_bound the one past the last, and the difference is the count. Show it in the demo on an array full of repeats.
  • Then say the practical thing: in C++ these are std::lower_bound and std::upper_bound, and you should use them — but you must be able to write them, because at the defence you will be asked to.

For the board

// first index with a[i] >= x
int l = 0, r = n;        // note: n, not n-1
while (l < r) {
    int m = l + (r - l) / 2;
    if (a[m] < x) l = m + 1;
    else          r = m;
}
// l is the answer, l == n means "no such element"
count of x = upper_bound(x) − lower_bound(x)
The invariant to say out loud: everything left of l is < x, everything from r on is ≥ x. When l == r the boundary is found. Teach the invariant, not the template — students who memorise the template cannot adapt it.

03

When there is no array to search

24 min demo: rope cutting

What to say

  • This is the beat that matters. Most of the lab is not searching a given array — there is no array.
  • The pattern: the answer is a number in a known range, and there is a yes/no check can(x) that is monotone — if x works then everything smaller works too. Then binary search the answer.
  • Say the three questions to ask on every such problem, in this order: what is the answer, what are its bounds, what is can(x) and is it monotone. Write them on the board and leave them up.
  • Work problem G live: n ropes, cut exactly k pieces, maximise the piece length. can(x) = "Σ⌊aᵢ/x⌋ ≥ k", which clearly only gets harder as x grows. Total cost O(n log(max a)).
  • Watch the direction. Here we want the largest x that works, so the loop keeps the good half: if (can(m)) l = m; else r = m - 1; — and m must round up or it hangs.
  • For real-valued answers do not use l < r. Run a fixed 100 iterations and stop; it is simpler and always terminates.

The template

bool can(long long x) { /* monotone check */ }

long long l = 1, r = MAXA;
while (l < r) {
    long long m = l + (r - l + 1) / 2;   // round UP
    if (can(m)) l = m;
    else        r = m - 1;
}
// l is the largest x with can(x) == true
Rounding up is not decoration. With l = m in the loop and m rounded down, l and r one apart make m == l forever. The submission hangs on a two-element test.
Check the empty answer. If even x = 1 fails, the answer is 0 and there is usually a special line to print. Problem G says so explicitly.

04

How to spot it in a statement

12 min board

What to say

  • Give them the vocabulary that signals it: "maximum such that", "minimum time to", "the largest k for which it is possible". Almost every one of those is a binary search on the answer.
  • Second signal: the direct computation is hopeless, but checking a candidate is easy. Robin Hood (F) is exactly that — you cannot compute the rate, but given a rate you can add up the hours in one pass.
  • Third: the answer range is huge (up to 10⁹ or 10¹⁸) while n is small. That mismatch is a giveaway — the log is over the values, not over n.
  • Warn them about the cost: the check runs inside the loop. An O(n) check gives O(n log C) overall, which is fine; an O(n²) check is not.

Where binary search hides

Two problems in the lab are binary search on something that is not a number line at all:

D · Win me if you can — sort the competitors once, then every round is a upper_bound plus a prefix sum. The search is over the sorted array; the work is in noticing you should sort first.

K · Snake — the array is never built (it can be 10⁹ cells). You binary search the column, then compute the row by formula. Pure "search a virtual structure".

B and E are the same problem twice. B has n, q ≤ 100 so a double loop passes; E raises both to 10⁵ and the double loop dies. Hand them out as a pair — solving B naively and then being forced to rewrite is the lesson.
05

Lab 3 — how it maps onto today

12 min ADS-Lab-03

What to say

  • A is the warm-up and should be done in the room, on the projector, in three minutes.
  • Then point at the split: A, B, D, E, K search inside data; C, F, G, I, J search over the answer. H is the odd one out — it is prefix sums plus a set, and it is there to stop the lab being monotonous.
  • Tell them the honest order of difficulty: A → D → F → G → C → J. Starting at J because it looks like a farm story is how people lose an evening.
  • Limits are mostly 1–2 s; J has 5 s because n = 2·10⁵ with a log inside a log.

What comes next

3 min

Lecture 4 is the binary search tree — the same halving idea, but built into the structure itself instead of applied to a flat array. Leave them with the question: a sorted array supports binary search in O(log n), so why would anyone need a tree? The answer is insertion, and it opens the next lecture.

Homework is Lab 3. Ask for A and G before the next class — one of each kind, so both templates get written at least once.
