01

The gap a sorted array leaves

14 min board

What to say

  • Recall last week honestly: a sorted array searches in O(log n) — but inserting into it is O(n), because everything after the insertion point shifts.
  • A linked list inserts in O(1) once you hold the node, but cannot binary search at all. Neither structure gives you both.
  • The BST is the compromise: search, insert and delete all O(h), where h is the height. Say height, not log n — the difference is the whole lecture.
  • The invariant, and write it exactly: for every node, all keys in the left subtree are smaller, all keys in the right subtree are larger. Not just the children — the entire subtree.

Three structures, one table

OperationSorted arrayLinked listBST
SearchO(log n)O(n)O(h)
InsertO(n)O(1)*O(h)
DeleteO(n)O(1)*O(h)
Sorted outputfreeO(n log n)O(n)

* once you already hold the node — finding it is still O(n).

h is not log n. It is log n only if the tree is balanced. Insert 1, 2, 3, …, n in order and you get a tree of height n — a linked list with extra pointers. Every problem in this lab lives or dies on which case it is.

For the board

struct Node {
    int key;
    Node *left, *right;
    Node(int k) : key(k), left(0), right(0) {}
};

Node* insert(Node* t, int k) {
    if (!t) return new Node(k);
    if (k < t->key) t->left  = insert(t->left,  k);
    else if (k > t->key) t->right = insert(t->right, k);
    return t;
}

02

Build it live

20 min demo: tree builder

What to say

  • Insert is one rule repeated: smaller goes left, larger goes right, keep walking until you fall off. Type keys into the demo and let the tree grow on the screen.
  • Then do the thing that makes the point: press "sorted 1…12" and watch the tree collapse into a diagonal. Height jumps from 4 to 12, and the readout says so.
  • Ask the room what input is worst for a BST. The answer — already sorted data — is counter-intuitive enough to be worth the pause.
  • Search is the same walk, returning when the key matches or the pointer is null. Minimum is leftmost, maximum is rightmost, both one straight descent.
  • Deletion has three cases: leaf, one child, two children. For two children you replace the key with its in-order successor — the leftmost node of the right subtree — and delete that instead.
  • Name the fix without teaching it: AVL and red-black trees rebalance on insert to keep h ≈ log n. std::set and std::map are red-black trees. That is why they never degrade the way today's code does.

03

In-order, and the other three

18 min demo: traversal order

What to say

  • Three depth-first orders, and they differ by one line moved: visit before the children (pre), between them (in), after them (post).
  • In-order on a BST prints the keys sorted. That is not a coincidence, it is the invariant read out loud — and it is the single most used fact in the lab.
  • Give each one a job: pre-order copies a tree, in-order sorts, post-order frees it (children before parent, or you delete the pointers you still need).
  • The fourth is level-order — a BFS with a queue, not recursion. It answers "what is on each level", which is problems D and E almost word for word.
  • Mention recursion depth: with h up to 10⁵ in the degenerate case, a recursive traversal can overflow the stack. On ejudge the import sets a 256 MB stack, so it survives — but say it, because elsewhere it will not.

For the board

void inorder(Node* t) {
    if (!t) return;
    inorder(t->left);
    cout << t->key << " ";   // ← move this line
    inorder(t->right);
}
// level order — a queue, not recursion
queue<Node*> q; q.push(root);
while (!q.empty()) {
    int sz = q.size();        // one full level
    while (sz--) {
        Node* v = q.front(); q.pop();
        if (v->left)  q.push(v->left);
        if (v->right) q.push(v->right);
    }
}
The int sz = q.size() line is what separates levels. Without it you get one flat list and problems D and E both fail.

The four readings, side by side

OrderWhere the visit happensWhat it is for
pre-orderbefore both childrencopy the tree — replay it into an empty BST
in-orderbetween the childrensorted output
post-orderafter both childrenfree the tree — children before the parent
levelqueue, not recursionper-level questions — problems D and E

Run all four in the demo of beat 02 on the same tree and read the output row out loud. In-order is the only one that comes out sorted, and that is the invariant of the structure, not a property of the traversal.

Switch the demo to sorted 1…10 first, then run in-order. The output is identical to a degenerate tree and to a balanced one — which is exactly why in-order cannot tell you anything about the shape.

One program, every operation

lecture04.md — class BST201 lines
#include <iostream>
using namespace std;

class Node {
    public:
    int data;
    Node *left, *right;

    Node(int data) {
        this->data = data;
        left = NULL;
        right = NULL;
    }
};

class BST {
    public:
    Node *root;

    BST() {
        root = NULL;
    }

    // Insert operation - O(log n) average, O(n) worst case
    Node *insert(Node *node, int data) {
        if (node == NULL) {
            node = new Node(data);
            return node;
        }

        if (data <= node->data) 
            node->left = insert(node->left, data);
        else
            node->right = insert(node->right, data);

        return node;
    }

    // In-order traversal - gives sorted output
    void inOrder(Node *node) {
        if (node == NULL)
            return;
        inOrder(node->left);
        cout << node->data << " ";
        inOrder(node->right);
    }

    // Pre-order traversal
    void preOrder(Node *node) {
        if (node == NULL)
            return;
        cout << node->data << " ";
        preOrder(node->left);
        preOrder(node->right);
    }

    // Post-order traversal
    void postOrder(Node *node) {
        if (node == NULL)
            return;
        postOrder(node->left);
        postOrder(node->right);
        cout << node->data << " ";
    }

    // Find minimum element - leftmost node
    Node *findMin(Node *node) {
        if (node == NULL)
            return NULL;
        while (node->left != NULL)
            node = node->left;
        return node;
    }

    // Find maximum element - rightmost node
    Node *findMax(Node *node) {
        if (node == NULL)
            return NULL;
        while (node->right != NULL)
            node = node->right;
        return node;
    }

    // Search for a value
    Node *search(Node *node, int data) {
        if (node == NULL || node->data == data)
            return node;
        
        if (data < node->data)
            return search(node->left, data);
        else
            return search(node->right, data);
    }

    // Delete operation - most complex
    Node *deleteNode(Node *node, int data) {
        if (node == NULL)
            return NULL;
            
        if (data < node->data)
            node->left = deleteNode(node->left, data);
        else if (data > node->data)
            node->right = deleteNode(node->right, data);
        else {
            // Node to be deleted found
            
            // Case 1: Node has no children (leaf node)
            if (node->right == NULL && node->left == NULL) {
                delete node;
                node = NULL;
            }
            // Case 2: Node has only right child
            else if (node->left == NULL) {
                Node *temp = node;
                node = node->right;
                delete temp;
            }
            // Case 3: Node has only left child
            else if (node->right == NULL) {
                Node *temp = node;
                node = node->left;
                delete temp;
            }
            // Case 4: Node has both children
            else {
                Node *tmp = findMax(node->left);  // Find inorder predecessor
                node->data = tmp->data;           // Replace data
                node->left = deleteNode(node->left, tmp->data);  // Delete predecessor
            }
        }
        return node;
    }

    // Helper function to get height of tree
    int getHeight(Node *node) {
        if (node == NULL)
            return 0;
        return 1 + max(getHeight(node->left), getHeight(node->right));
    }

    // Count total nodes in tree
    int countNodes(Node *node) {
        if (node == NULL)
            return 0;
        return 1 + countNodes(node->left) + countNodes(node->right);
    }
};

int main() {
    BST *bst = new BST();
    
    // Insert nodes
    bst->root = bst->insert(bst->root, 10);
    bst->root = bst->insert(bst->root, 15);
    bst->root = bst->insert(bst->root, 16);
    bst->root = bst->insert(bst->root, 13);
    bst->root = bst->insert(bst->root, 12);
    bst->root = bst->insert(bst->root, 14);
    bst->root = bst->insert(bst->root, 9);
    bst->root = bst->insert(bst->root, 8);
    bst->root = bst->insert(bst->root, 10);  // Duplicate - goes to left
    bst->root = bst->insert(bst->root, 10);  // Another duplicate
    bst->root = bst->insert(bst->root, 17);

    cout << "In-order traversal (sorted): ";
    bst->inOrder(bst->root);
    cout << endl;

    cout << "Pre-order traversal: ";
    bst->preOrder(bst->root);
    cout << endl;

    cout << "Post-order traversal: ";
    bst->postOrder(bst->root);
    cout << endl;

    // Find min and max
    Node *node_min = bst->findMin(bst->root);
    Node *node_max = bst->findMax(bst->root);
    cout << "Min: " << node_min->data << ", Max: " << node_max->data << endl;

    // Search for a value
    Node *found = bst->search(bst->root, 13);
    if (found)
        cout << "Found: " << found->data << endl;
    else
        cout << "Not found" << endl;

    // Tree statistics
    cout << "Tree height: " << bst->getHeight(bst->root) << endl;
    cout << "Total nodes: " << bst->countNodes(bst->root) << endl;

    // Delete a node
    cout << "Deleting node 13..." << endl;
    bst->root = bst->deleteNode(bst->root, 13);
    cout << "In-order after deletion: ";
    bst->inOrder(bst->root);
    cout << endl;

    return 0;
}

Duplicates go left here. data <= node->data keeps repeated keys, which is why 10 is printed three times. The board code of beat 01 and the demo of beat 02 skip a key that is already present. Both are legitimate — say which one a problem needs, because it changes the answer to every "count" question.

What the tree in that main looks like

          10
        /    \
       9      15
      / \    /  \
     8  10  13   16
        /   / \    \
      10  12  14   17

Both extra 10s walk left at the root, then right at 9. That is why the height is 4, not 3, and why the pre-order starts 10 9 8 10 10.

The notes' own example is wrong for this tree. lecture04.md says "delete 9 — it has only the left child 8". With the duplicates inserted, 9 has two children, 8 and 10. Use 16 (only the right child 17) for the one-child case, and 8, 12, 14, 17 for leaves.

Deleting — the three cases

CaseWhat happensExample on this tree
leafunlink it, free it8, 12, 14, 17
one childthe child takes the node's place16 → 17 moves up
two childrencopy in the predecessor or the successor, then delete that one13, 15, 10 (root)

The 2025 code takes the in-order predecessor — the maximum of the left subtree. The demo of beat 02 and the week-4 files take the successor — the minimum of the right subtree. They are mirror images; either keeps the invariant. The one that matters is that the replacement has at most one child, so deleting it is case 1 or 2 and the recursion stops there.

Cost of each operation

OperationBestAverageWorst
SearchO(1)O(log n)O(n)
InsertO(1)O(log n)O(n)
DeleteO(1)O(log n)O(n)
Find min / maxO(1)O(log n)O(n)
Any traversalO(n)O(n)O(n)

Every non-traversal row is really O(h). Best is the key at the root, average is a tree built from random order, worst is the degenerate list — press sorted 1…10 in the demo. Memory is O(n) for the nodes, plus O(h) of call stack for the recursive versions.

#include <iostream>

using namespace std;

class Node {
    public:
    int data;
    Node *left;
    Node *right;
    Node *parent;
    Node(int data) {
        this->data = data;
        left = NULL;
        right = NULL;
    }
};

class Tree {
    public:
    Node *root;

    Node* insert_node(Node *node, int data) {
        if (node == NULL) {
            Node *node = new Node(data);
            return node;
        }
        if (node->data < data) 
            node->right = insert_node(node->right, data);
        else
            node->left = insert_node(node->left, data);
        return node;
    }

    void insert_node2(int data) {
        if (this->root == NULL) {
            this->root = new Node(data);
            return;
        }
        Node *cur = root;
        while (cur != NULL) {
            if (data > cur->data) {
                if (cur->right == NULL) {
                    cur->right = new Node(data);
                    break;
                } else
                    cur = cur->right;
            } else {
                if (cur->left == NULL) {
                    cur->left = new Node(data);
                    break;
                } else 
                    cur = cur->left;
            }
        }
    }

    void in_order(Node *node) {
        if (node == NULL)
            return;
        in_order(node->left);
        cout << node->data << " ";
        in_order(node->right);
    }

    Node* find_min(Node *node) {
        if (node->left == NULL)
            return node;
        return find_min(node->left);
    }

    Node *find_min2(Node *node) {
        while (node->left != NULL)
            node = node->left;
        return node;
    }

    Node *delete_node(Node *node, int data) {
        if (node == NULL)
            return NULL;
        if (data < node->data)
            node->left = delete_node(node->left, data);
        else if (data > node->data)
            node->right = delete_node(node->right, data);
        else {
            if (node->right == NULL and node->left == NULL)
                node = NULL;
            else if (node->left == NULL) 
                node = node->right;
            else if (node->right == NULL)
                node = node->left;
            else {
                Node *tmp = find_min(node->right);
                node->data = tmp->data;
                node->right = delete_node(node->right, tmp->data);
            }
        }
        return node;
    }
};

Four things to fix before showing it

2.cpp · delete_node never returns the node. The function ends after the else block with no return node;. g++ only warns (-Wreturn-type), and the output above looks fine only because main never calls delete. Any call is undefined behaviour: the parent gets a garbage pointer. One line fixes it — a good "find the bug" moment.
1.cpp · Tree has no constructor. root is NULL only because new Tree() — with the parentheses — value-initialises it. Write new Tree or Tree t; and root is garbage, so insert_node2 dereferences it on the first call. 2.cpp adds the constructor; say why.
1.cpp · parent is declared and never set. The field stays uninitialised and nothing reads it. Either drop it (2.cpp comments it out) or maintain it on every insert and delete — half-done is worse than absent.
Both files · deleted nodes are never freed. The node is unlinked but not deleted. On a lab-sized input nobody notices; the lecture04.md version does free them, with a temp pointer in the one-child cases.

Where the BST fits

reference lecture04.md

Against the other structures

StructureSearchInsertDeleteMemory
Array, unsortedO(n)O(1)O(n)O(n)
Array, sortedO(log n)O(n)O(n)O(n)
Linked listO(n)O(1)O(n)O(n)
BST, balancedO(log n)O(log n)O(log n)O(n)
Hash tableO(1)*O(1)*O(1)*O(n)

* on average — lecture 8. A hash table is faster, but it has no order: no min, no "next larger", no range, no sorted output.

Strengths and weaknesses

Good atBad at
search in O(log n) on averagecan degenerate — O(n) on sorted input
sorted output for free — in-orderno O(1) operations, unlike a hash table
grows and shrinks at runtimeno access by index — no a[i]
range queries: every key between x and ymore code than an array for simple jobs

Reach for it when the data changes and you keep needing order: frequent search, min/max, "the next key after x", everything in a range. Do not when access is mostly sequential, when you need the i-th element, or when only exact lookup matters — that is a hash table.

Five things to leave with

  1. The order lives in the structure: left subtree smaller, right subtree larger — at every node.
  2. Speed depends on balance: O(log n) when balanced, O(n) when it has become a list.
  3. In-order traversal always prints the keys sorted.
  4. Delete is the hard operation — three cases, and the third reduces to the first two.
  5. The BST is the base of AVL and red-black trees — and red-black is what std::set and std::map are.
