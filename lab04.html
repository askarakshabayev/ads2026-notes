01

Introduction to Binary Search Tree

8 min board

What to say

  • A Binary Search Tree is a binary tree in which every node holds a key and the keys obey one ordering property.
  • All nodes in the left subtree of a node are strictly less than it; all nodes in the right subtree are strictly greater. The whole subtree, not only the child.
  • That property is what makes search, insertion and deletion efficient — especially while the tree stays balanced.

The ordering property

  1. Left subtree — every key strictly less than the node's key.
  2. Right subtree — every key strictly greater than the node's key.

Draw it for the keys of today's program, 10 15 16 13 12 14 9 8 17:

        10
       /  \
      9    15
     /    /  \
    8    13   16
        /  \    \
       12  14    17

Check the rule at 15: its left subtree is 13, 12, 14 — all smaller; its right subtree is 16, 17 — all larger. And the whole right half of the tree is larger than the root 10.

BST Properties

12 min demo: tree builder

What to say

  • In-order traversal of a BST gives the elements in sorted order. Show it: build a tree in the demo and run in-order.
  • Search, insert and delete are O(log n) on average — each step goes down one level.
  • The worst case is O(n) — a skewed tree. Press sorted 1…10: the tree becomes a diagonal, height 10 instead of 4.
  • Space is O(n) — one node per key.

What to say

  • Write the program top to bottom, one function at a time: the node, the class, insert, traversals, min and max, search, delete, height and count, then main.
  • Every recursive function has the same shape: stop at NULL, otherwise go left or right by comparing with the key.
  • Insert returns the (sub)tree root and the caller reattaches it: node->left = insert(node->left, data). The same trick is used by delete.
  • Then show two more versions of the same program: the loop version of insert and of find_min next to the recursive ones — the same walk down, written two ways.

1 · The node

#include <iostream>
using namespace std;

class Node {
    public:
    int data;
    Node *left, *right;

    Node(int data) {
        this->data = data;
        left = NULL;
        right = NULL;
    }
};

A key and two pointers. A new node has no children, so both start as NULL.

2 · The tree and insert

class BST {
    public:
    Node *root;

    BST() {
        root = NULL;
    }
    ...
};
// Insert operation - O(log n) average, O(n) worst case
Node *insert(Node *node, int data) {
    if (node == NULL) {
        node = new Node(data);
        return node;
    }

    if (data <= node->data) 
        node->left = insert(node->left, data);
    else
        node->right = insert(node->right, data);

    return node;
}

Walk down until a NULL, create the node there, and return it so the parent links it in. Equal keys go left here (<=).

4 · Minimum, maximum, search

// Find minimum element - leftmost node
Node *findMin(Node *node) {
    if (node == NULL)
        return NULL;
    while (node->left != NULL)
        node = node->left;
    return node;
}

// Find maximum element - rightmost node
Node *findMax(Node *node) {
    if (node == NULL)
        return NULL;
    while (node->right != NULL)
        node = node->right;
    return node;
}
// Search for a value
Node *search(Node *node, int data) {
    if (node == NULL || node->data == data)
        return node;
    
    if (data < node->data)
        return search(node->left, data);
    else
        return search(node->right, data);
}

Minimum is the leftmost node, maximum the rightmost. Search is insert without the insertion: stop when the key matches or the pointer is NULL.

5 · Delete

// Delete operation - most complex
Node *deleteNode(Node *node, int data) {
    if (node == NULL)
        return NULL;
        
    if (data < node->data)
        node->left = deleteNode(node->left, data);
    else if (data > node->data)
        node->right = deleteNode(node->right, data);
    else {
        // Node to be deleted found
        
        // Case 1: Node has no children (leaf node)
        if (node->right == NULL && node->left == NULL) {
            delete node;
            node = NULL;
        }
        // Case 2: Node has only right child
        else if (node->left == NULL) {
            Node *temp = node;
            node = node->right;
            delete temp;
        }
        // Case 3: Node has only left child
        else if (node->right == NULL) {
            Node *temp = node;
            node = node->left;
            delete temp;
        }
        // Case 4: Node has both children
        else {
            Node *tmp = findMax(node->left);  // Find inorder predecessor
            node->data = tmp->data;           // Replace data
            node->left = deleteNode(node->left, tmp->data);  // Delete predecessor
        }
    }
    return node;
}

Find the node as in search, then one of the cases. With two children the node takes the key of its in-order predecessor — the maximum of the left subtree — and that node is deleted instead. The cases are drawn step by step in Deletion Cases in Detail.

6 · Height and node count

// Helper function to get height of tree
int getHeight(Node *node) {
    if (node == NULL)
        return 0;
    return 1 + max(getHeight(node->left), getHeight(node->right));
}

// Count total nodes in tree
int countNodes(Node *node) {
    if (node == NULL)
        return 0;
    return 1 + countNodes(node->left) + countNodes(node->right);
}

Both are "answer for the left + answer for the right + this node". An empty tree has height 0 and 0 nodes.

Tree Traversals

10 min board

What to say

  • In-order — left, root, right. The result is the elements in sorted order; use it to get a sorted sequence from a BST.
  • Pre-order — root, left, right. The root comes first; use it to create a copy of the tree.
  • Post-order — left, right, root. The root comes last; use it to delete the tree safely — children before the parent.

Three orders

TraversalOrderResultUse case
In-orderLeft → Root → Rightelements in sorted ordersorted sequence from a BST
Pre-orderRoot → Left → Rightroot comes firstcreating a copy of the tree
Post-orderLeft → Right → Rootroot comes lastdeleting the tree safely

BST Operations Analysis

6 min board

What to say

  • Every operation except traversal walks one path from the root, so its cost is the height of the tree.
  • Best case — the key is at the root. Average — a tree built from random order, height about log n. Worst — the skewed tree, height n.

Deletion Cases in Detail

15 min board

What to say

  • Case 1 — a leaf. Simply remove the node. Example: delete 8.
  • Case 2 — one child. Replace the node with its child. Example: delete 9 — it has only the left child 8.
  • Case 3 — two children. Find the in-order predecessor (the rightmost node of the left subtree) or the in-order successor (the leftmost node of the right subtree), copy its value into the node, then delete the predecessor or successor.
  • The predecessor has no right child, the successor no left child — so deleting it is always case 1 or 2.

Case 1 · a leaf

Simply remove the node. On the tree from the introduction: delete 8 — 9 loses its left child, nothing else changes.

Case 2 · one child

Replace the node with its child. Delete 9 — it has only the left child 8, so 8 takes its place under 10.

Case 3 · two children

  • Find the in-order predecessor — the rightmost node in the left subtree — or the in-order successor — the leftmost node in the right subtree.
  • Replace the node's data with the predecessor's / successor's.
  • Delete the predecessor / successor.

Delete 15 with the predecessor, as deleteNode above does: the rightmost key of its left subtree is 14.

        10                        10
       /  \                      /  \
      9    15          →        9    14
     /    /  \                 /    /  \
    8    13   16              8    13   16
        /  \    \                 /      \
       12  14    17              12       17

With the successor it would be 16 instead — version 3 of the program does it that way. Both keep the ordering property.

BST vs Other Data Structures

5 min board

What to say

  • A sorted array searches fast but inserts slowly; a linked list inserts fast but searches slowly. A balanced BST does all three in O(log n).
  • A hash table is O(1) on average, but it keeps no order.

Advantages and Disadvantages

4 min board

Advantages

  • Efficient searching: O(log n) average case
  • In-order traversal gives a sorted sequence
  • Dynamic size: can grow and shrink during runtime
  • No extra space needed for sorting

Disadvantages

  • Can become unbalanced → O(n) worst case
  • No constant time operations like hash tables
  • More complex than arrays for simple operations
09

When to Use BST

4 min board

Good for

  • Frequent search operations
  • Need to maintain sorted order
  • Range queries (find all elements between x and y)
  • Dynamic data with insertions and deletions

Not ideal for

  • Mostly sequential access
  • Frequent random access by index
  • When constant time operations are critical
10

Key Takeaways

3 min

Five things to remember

  1. A BST maintains sorted order through its structure property.
  2. Performance depends on tree balance — a balanced tree gives O(log n), a skewed tree gives O(n).
  3. In-order traversal always gives sorted output.
  4. Deletion is the most complex operation, with three different cases.
  5. The BST is the foundation for more advanced trees like AVL and Red-Black trees.
