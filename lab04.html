01

The gap a sorted array leaves

14 min board

What to say

  • Recall last week honestly: a sorted array searches in O(log n) — but inserting into it is O(n), because everything after the insertion point shifts.
  • A linked list inserts in O(1) once you hold the node, but cannot binary search at all. Neither structure gives you both.
  • The BST is the compromise: search, insert and delete all O(h), where h is the height. Say height, not log n — the difference is the whole lecture.
  • The invariant, and write it exactly: for every node, all keys in the left subtree are smaller, all keys in the right subtree are larger. Not just the children — the entire subtree.

Three structures, one table

OperationSorted arrayLinked listBST
SearchO(log n)O(n)O(h)
InsertO(n)O(1)*O(h)
DeleteO(n)O(1)*O(h)
Sorted outputfreeO(n log n)O(n)

* once you already hold the node — finding it is still O(n).

h is not log n. It is log n only if the tree is balanced. Insert 1, 2, 3, …, n in order and you get a tree of height n — a linked list with extra pointers. Every problem in this lab lives or dies on which case it is.

For the board

struct Node {
    int key;
    Node *left, *right;
    Node(int k) : key(k), left(0), right(0) {}
};

Node* insert(Node* t, int k) {
    if (!t) return new Node(k);
    if (k < t->key) t->left  = insert(t->left,  k);
    else if (k > t->key) t->right = insert(t->right, k);
    return t;
}

02

Build it live

20 min demo: tree builder

What to say

  • Insert is one rule repeated: smaller goes left, larger goes right, keep walking until you fall off. Type keys into the demo and let the tree grow on the screen.
  • Then do the thing that makes the point: press "sorted 1…12" and watch the tree collapse into a diagonal. Height jumps from 4 to 12, and the readout says so.
  • Ask the room what input is worst for a BST. The answer — already sorted data — is counter-intuitive enough to be worth the pause.
  • Search is the same walk, returning when the key matches or the pointer is null. Minimum is leftmost, maximum is rightmost, both one straight descent.
  • Deletion has three cases: leaf, one child, two children. For two children you replace the key with its in-order successor — the leftmost node of the right subtree — and delete that instead.
  • Name the fix without teaching it: AVL and red-black trees rebalance on insert to keep h ≈ log n. std::set and std::map are red-black trees. That is why they never degrade the way today's code does.

03

In-order, and the other three

18 min demo: traversal order

What to say

  • Three depth-first orders, and they differ by one line moved: visit before the children (pre), between them (in), after them (post).
  • In-order on a BST prints the keys sorted. That is not a coincidence, it is the invariant read out loud — and it is the single most used fact in the lab.
  • Give each one a job: pre-order copies a tree, in-order sorts, post-order frees it (children before parent, or you delete the pointers you still need).
  • The fourth is level-order — a BFS with a queue, not recursion. It answers "what is on each level", which is problems D and E almost word for word.
  • Mention recursion depth: with h up to 10⁵ in the degenerate case, a recursive traversal can overflow the stack. On ejudge the import sets a 256 MB stack, so it survives — but say it, because elsewhere it will not.

For the board

void inorder(Node* t) {
    if (!t) return;
    inorder(t->left);
    cout << t->key << " ";   // ← move this line
    inorder(t->right);
}
// level order — a queue, not recursion
queue<Node*> q; q.push(root);
while (!q.empty()) {
    int sz = q.size();        // one full level
    while (sz--) {
        Node* v = q.front(); q.pop();
        if (v->left)  q.push(v->left);
        if (v->right) q.push(v->right);
    }
}
The int sz = q.size() line is what separates levels. Without it you get one flat list and problems D and E both fail.

04

Lab 4 — how it maps onto today

14 min ADS-Lab-04

What to say

  • Five problems are "build the tree, then answer one question about it": B, C, H, I, J. They all start with the same fifteen lines from beat 02.
  • D and E are the level-order pair — D asks for the sum per level, E for the widest level. Both are the queue loop from beat 03.
  • A is the odd one: the tree is given as edges, not built by insertion, and you follow a path of L/R instructions. Read the input format carefully with them.
  • Warn them off F and G. F counts nodes per depth on n = 10⁴ with TL 3 s, G is the tree diameter on n = 2·10⁴ with TL 5 s. Both are real work and neither is on the defence.
  • J is the one worth doing carefully: k-th smallest is in-order traversal with a counter, stopping early. Doing it by collecting everything into a vector also passes here, but it is the wrong habit.

05

What comes next

3 min

Lecture 5 is the heap — a tree that gives up total order and keeps only one guarantee: the smallest element is at the root. Set it up with the contrast: today's tree can answer "is 47 here", the heap cannot — but it never degenerates into a list, because it is stored in an array and is balanced by construction.

Homework is Lab 4. Ask for B and J before the next class — the first is the bare skeleton, the second is that skeleton plus one counter.
