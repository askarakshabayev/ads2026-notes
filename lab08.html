Introduction to Hashing

15 min board demo: hash

What to say

  • Hashing converts data — strings, numbers, objects — into a fixed-size number, the hash value. It acts as a fingerprint of the data.
  • A good hash function is deterministic, fast — O(n) for a string of length n — spreads values evenly, and rarely gives two inputs the same value.
  • Why bother: comparing two strings is O(n), comparing two numbers is O(1). Compute each hash once and every later comparison is cheap.
  • The polynomial rolling hash: multiply each character by the next power of p and add. Work the example for "abc" on the board, then let the demo compute a few more.

What is a hash function?

A hash function takes an input and produces a number. With the function written below (p = 29):

hash("hello")  → 81236064
hash("world")  → 73461324
hash("abc")    → 86198

Properties of good hash functions

  1. Deterministic: the same input always produces the same output
  2. Fast to compute: O(n) for a string of length n
  3. Uniform distribution: hash values spread evenly
  4. Minimizes collisions: different inputs should produce different hashes (ideally)

Why do we need hashing?

Compare two stringsFind duplicates among n strings
Without hashingO(n) — check each characterO(n² × m)
With hashingO(1) — compare two integersO(n × m) — one hash per string

m is the length of a string.

Polynomial rolling hash

hash(s) = s[0] × p^0 + s[1] × p^1 + s[2] × p^2 + …
  • p is a prime, commonly 29 or 31 for lowercase letters
  • s[i] is the ASCII code of the character at position i

Example: hash("abc") with p = 29

hash = 'a' × 29^0 + 'b' × 29^1 + 'c' × 29^2
     = 97 × 1 + 98 × 29 + 99 × 841
     = 97 + 2842 + 83259
     = 86198

Simple hash implementation

#include <iostream>
using namespace std;

int get_hash(string s) {
    int p = 29;
    int p_pow = 1;  // p^0
    int h = 0;

    for (int i = 0; i < s.size(); i++) {
        h += s[i] * p_pow;
        p_pow *= p;
    }

    return h;
}

int main() {
    cout << "hash('abc') = " << get_hash("abc") << endl;
    cout << "hash('hello') = " << get_hash("hello") << endl;
    cout << "hash('world') = " << get_hash("world") << endl;

    return 0;
}
output
hash('abc') = 86198
hash('hello') = 81236064
hash('world') = 73461324

Problem 1: Finding Identical Strings

10 min code

What to say

  • Given n strings, find all pairs of identical ones. Comparing every pair is O(n² × m).
  • With hashing: compute each hash once, group the indices by hash in a map, and compare strings only inside a group — the check against collisions.

Naive solution — O(n² × m)

// Compare each pair of strings
for (int i = 0; i < n; i++) {
    for (int j = i + 1; j < n; j++) {
        if (strings[i] == strings[j]) {  // O(m) comparison
            cout << i << " " << j << endl;
        }
    }
}

// Time Complexity: O(n² × m)
// where n = number of strings, m = average string length

Improved solution with hashing — O(n × m)

  1. Compute the hash of each string — O(m) per string
  2. Store the hashes in a map
  3. Compare hash values instead of strings — O(1)
#include <iostream>
#include <vector>
#include <map>
using namespace std;

int get_hash(string s) {
    int p = 29;
    int p_pow = 1;
    int h = 0;
    for (int i = 0; i < s.size(); i++) {
        h += s[i] * p_pow;
        p_pow *= p;
    }
    return h;
}

int main() {
    int n;
    cin >> n;

    vector<string> strings(n);
    map<int, vector<int>> hash_map;  // hash -> indices

    // Compute hash for each string and group by hash
    for (int i = 0; i < n; i++) {
        cin >> strings[i];
        int h = get_hash(strings[i]);
        hash_map[h].push_back(i);
    }

    // Find pairs with same hash
    cout << "Identical string pairs:" << endl;
    for (auto& pair : hash_map) {
        vector<int>& indices = pair.second;
        // All strings with same hash are potentially identical
        for (int i = 0; i < indices.size(); i++) {
            for (int j = i + 1; j < indices.size(); j++) {
                // Double-check actual strings to avoid hash collisions
                if (strings[indices[i]] == strings[indices[j]]) {
                    cout << indices[i] << " " << indices[j] << endl;
                }
            }
        }
    }

    return 0;
}

5
hello
world
hello
test
world
output
Identical string pairs:

0 2

Pairs come out grouped by hash, in the order of the map keys: hash("world") is smaller than hash("hello"), so 1 4 is printed first.

Time complexity: O(n × m)

  • Computing hashes: O(n × m)
  • Grouping by hash: O(n)
  • Finding pairs: O(n) if there are no collisions

Instead of O(n² × m) we get O(n × m).

Prefix Hash Array — Fast Substring Hash

10 min board

What to say

  • A string of length n has O(n²) substrings; hashing each from scratch is O(n) — O(n³) in total.
  • Precompute prefix hashes once: h[i] is the hash of s[0…i]. Then the hash of any substring is one subtraction.
  • The subtraction gives the hash multiplied by p^l. We cannot divide, so we multiply the other side instead.

The problem

  • A string of length n has O(n²) substrings
  • Computing each hash takes O(m)
  • Total: O(n³) — too slow

Prefix hash array

h[i] = hash of the prefix s[0…i]:

h[i] = s[0] × p^0 + s[1] × p^1 + … + s[i] × p^i
vector<int> get_h(string s) {
    int n = s.size();
    vector<int> h(n);

    h[0] = s[0];          // First character
    int p = 29;
    int p_pow = 29;       // p^1

    for (int i = 1; i < n; i++) {
        h[i] = h[i - 1] + s[i] * p_pow;
        p_pow *= p;
    }

    return h;
}

Example: s = "abcd", p = 29

h[0] = 'a' × p^0 = 97
h[1] = 'a' × p^0 + 'b' × p^1 = 2939
h[2] = 'a' × p^0 + 'b' × p^1 + 'c' × p^2 = 86198
h[3] = 'a' × p^0 + 'b' × p^1 + 'c' × p^2 + 'd' × p^3 = 2525098

Getting the hash of any substring

hash(s[l...r]) = (h[r] - h[l-1]) / p^l

But we cannot divide, so we multiply the other side:

hash(s[l...r]) × p^l = h[r] - h[l-1]
// Precompute powers of p
vector<int> p(n);
p[0] = 1;
for (int i = 1; i < n; i++)
    p[i] = p[i - 1] * 29;

// Get hash of substring [l, r]
int substring_hash(int l, int r) {
    int hash = h[r];
    if (l > 0)
        hash = hash - h[l - 1];
    return hash;  // This equals original_hash × p^l
}

So to compare two substrings, bring both to the same power of p before comparing.

Rabin-Karp Algorithm: Pattern Matching

20 min code demo: search

What to say

  • Find every occurrence of a pattern s2 (length m) in a text s1 (length n). Comparing at every position is O(n × m).
  • Rabin–Karp: hash the pattern once, compute prefix hashes of the text, and at each position compare one number with one number.
  • The window hash is h[j] − h[i−1], which equals the real hash × p^i — so compare it with h_s2 × p[i].
  • Walk through the trace for "ababcab" and "ab" on the board, then search a longer text in the demo.

Naive approach — O(n × m)

for (int i = 0; i <= n - m; i++) {
    bool match = true;
    for (int j = 0; j < m; j++) {
        if (s1[i + j] != s2[j]) {
            match = false;
            break;
        }
    }
    if (match)
        cout << "Found at position " << i << endl;
}

Rabin–Karp — O(n + m)

  1. Compute the hash of the pattern s2
  2. Compute the prefix hashes of the text s1
  3. At each position i, compare the hash of the window with the pattern hash
  4. Compare the actual strings only if the hashes match — to handle collisions

Complete implementation

// unsigned long long: with int the hash overflows already at 7 characters
#include <iostream>
#include <vector>

using namespace std;

// Compute hash of entire string
unsigned long long get_hash(string s) {
    unsigned long long p = 29;
    unsigned long long p_pow = 1;  // p^0
    unsigned long long h = 0;

    for (int i = 0; i < s.size(); i++) {
        h += s[i] * p_pow;
        p_pow *= p;
    }

    return h;
}

// Compute prefix hash array
vector<unsigned long long> get_h(string s) {
    int n = s.size();
    vector<unsigned long long> h(n);

    h[0] = s[0];
    unsigned long long p = 29;
    unsigned long long p_pow = 29;  // p^1

    for (int i = 1; i < n; i++) {
        h[i] = h[i - 1] + s[i] * p_pow;
        p_pow *= p;
    }

    return h;
}

int main() {
    string s1, s2;
    cin >> s1 >> s2;

    // Precompute powers of p
    vector<unsigned long long> p(s1.size());
    p[0] = 1;
    for (int i = 1; i < s1.size(); i++)
        p[i] = p[i - 1] * 29;

    // Hash of pattern
    unsigned long long h_s2 = get_hash(s2);

    // Prefix hashes of text
    vector<unsigned long long> h = get_h(s1);

    int n = s1.size();
    int m = s2.size();

    // Find all occurrences
    for (int i = 0; i < n - m + 1; i++) {
        int j = i + m - 1;  // End of current window

        // Get hash of substring s1[i...j]
        unsigned long long hash = h[j];
        if (i > 0)
            hash = hash - h[i - 1];

        // Compare with pattern hash
        // hash = actual_hash × p^i, so compare with h_s2 × p^i
        if (hash == h_s2 * p[i])
            cout << i << " ";
    }

    return 0;
}

Problem 2: Count Distinct Substrings

10 min code

What to say

  • Count the distinct substrings of a string. Putting every substring into a set of strings is O(n³).
  • Put their hashes into a set instead — O(n² log n). Each hash must be brought to the same power of p first, or one substring at two positions counts twice.

Naive solution — O(n³)

set<string> distinct;
for (int i = 0; i < n; i++) {
    for (int j = i; j < n; j++) {
        string sub = s.substr(i, j - i + 1);  // O(n)
        distinct.insert(sub);  // O(n log n) for set insertion
    }
}
cout << distinct.size() << endl;

// Time: O(n² × n) = O(n³)

Improved solution with hashing — O(n² log n)

#include <iostream>
#include <vector>
#include <set>
using namespace std;

vector<unsigned long long> get_h(string s) {
    int n = s.size();
    vector<unsigned long long> h(n);

    h[0] = s[0];
    unsigned long long p = 29;
    unsigned long long p_pow = 29;

    for (int i = 1; i < n; i++) {
        h[i] = h[i - 1] + s[i] * p_pow;
        p_pow *= p;
    }

    return h;
}

int main() {
    string s;
    cin >> s;

    int n = s.size();

    // Precompute powers
    vector<unsigned long long> p(n);
    p[0] = 1;
    for (int i = 1; i < n; i++)
        p[i] = p[i - 1] * 29;

    // Compute prefix hashes
    vector<unsigned long long> h = get_h(s);

    // Use set to store unique hashes
    set<unsigned long long> distinct_hashes;

    // Generate all substrings
    for (int i = 0; i < n; i++) {
        for (int j = i; j < n; j++) {
            // Hash of substring [i, j]
            unsigned long long hash = h[j];
            if (i > 0)
                hash = hash - h[i - 1];

            // added: h[j] - h[i-1] is hash × p^i — bring every substring to p^(n-1),
            // otherwise the same substring at two positions gives two numbers
            distinct_hashes.insert(hash * p[n - 1 - i]);  // O(log n)
        }
    }

    cout << "Number of distinct substrings: ";
    cout << distinct_hashes.size() << endl;

    return 0;
}

Hash Collisions

10 min code

What to say

  • A collision is two different strings with the same hash.
  • There are infinitely many strings and finitely many hash values — by the pigeonhole principle, collisions are unavoidable.
  • Four defences: bigger hash values, a large prime modulus, two hash functions at once, and comparing the strings when the hashes match.

What is a collision?

hash("abc") == hash("xyz")  // Collision!

Why do collisions happen?

  • Hash values are integers — a finite range
  • Strings are infinite in variety
  • By the pigeonhole principle, collisions are inevitable

1 · Use larger hash values (long long, unsigned long long)

unsigned long long get_hash(string s) {
    unsigned long long p = 29;
    unsigned long long p_pow = 1;
    unsigned long long h = 0;
    for (int i = 0; i < s.size(); i++) {
        h += s[i] * p_pow;
        p_pow *= p;
    }
    return h;
}

2 · Use modulo with a large prime

const long long MOD = 1e9 + 7;  // Large prime

int get_hash(string s) {
    long long h = 0;
    long long p_pow = 1;
    long long p = 29;

    for (int i = 0; i < s.size(); i++) {
        h = (h + s[i] * p_pow) % MOD;
        p_pow = (p_pow * p) % MOD;
    }

    return h;
}

3 · Double hashing — two different hash functions

pair<int, int> double_hash(string s) {
    int h1 = get_hash(s, 29, MOD1);
    int h2 = get_hash(s, 31, MOD2);
    return {h1, h2};
}

4 · Verify with an actual string comparison when hashes match

if (hash1 == hash2) {
    // Don't assume strings are equal!
    if (s1 == s2) {
        // Actually equal
    }
}

Advantages and Disadvantages

3 min

Advantages

  • Fast comparison: O(1) instead of O(n)
  • Space efficient: store an integer instead of a string
  • Versatile: works for strings, arrays, objects
  • Simple to implement: the basic version is straightforward

Disadvantages

  • Collisions possible: different inputs may have the same hash
  • No guaranteed uniqueness: critical applications need verification
  • Overflow issues: large values need careful handling
  • Choice of parameters: p and MOD affect the collision rate
09

Common Questions

6 min

Q1 · Why use prime numbers (29, 31) for p?

Prime numbers reduce the probability of collisions — they spread the hash values better across the range.

Q2 · What if hash values overflow?

  • Use long long or unsigned long long
  • Use modulo with a large prime: hash = (hash + value) % MOD
  • Both work — choose based on the requirements

With plain int the hash of a 7-character string already overflows; signed overflow is undefined behaviour in C++, unsigned overflow simply wraps around.

Q3 · Can we always trust hash equality?

No. When correctness is critical, verify with an actual comparison:

if (hash1 == hash2 && str1 == str2) {
    // Strings are definitely equal
}

Q4 · Rabin–Karp or KMP for pattern matching?

  • Rabin–Karp: simpler, works for multiple patterns, small chance of a collision
  • KMP: more involved, but no false positives — better for a single pattern

Q5 · Why O(n² log n) for counting distinct substrings?

  • O(n²) to generate all substrings
  • O(log n) to insert each hash into a set (a balanced tree)
  • Total: O(n² log n)
10

Key Takeaways

3 min

Eight things to remember

  1. Hashing converts strings to integers for fast comparison
  2. Polynomial rolling hash is the most common for strings: hash = Σ s[i] × p^i
  3. A prefix hash array answers substring hash queries in O(1)
  4. Rabin–Karp finds a pattern in O(n + m)
  5. Hash collisions are possible — verify when necessary
  6. Hashing improves complexity — from O(n³) to O(n² log n) or better
  7. Choose good parameters: p = 29 or 31, MOD = a large prime
  8. Trade-off: speed against a small collision probability
